# 0266. Keep controller maps flat, up to 90 rows a Part in ITCM, and ship one map an engine

- **Status:** Proposed (supersedes in part 0226: its sections, the layer, `MapSection` as the written record, the 16-row layer and the 32-slot resolution; supersedes 0264: SUGGEST; amends 0217, whose 32 binding slots now hold the Sound's 16 and 16 seats, and 0255, whose row edits, saves and console `put` act on a flat file)
- **Deciders:** owner (2026-11-12: "makes sense" to the model, "sounds good" to the design), firmware

## Context
The owner's model: a controller map is "just a bunch of mini learn stuff", one flat list of rows (control → cell, with the row's MIN, MAX, INPUT and ECHO), with no shared or engine sections. The factory set ships one map an engine, named after it (ALGO, MODAL, VA, TAPE, and DRUM once the drum engine ships), each as rich as the rows allow: "here's how we did it, you can do it any way you like." Any map plays on any engine. A row for a cell the Part's engine lacks dims and does nothing. A Part holds a map only once it picks one, NONE holds nothing, and the map stays with the Part across Sound loads. The Sound's own learned rows stay 16 a Part and win over the map's rows on the same control.

A RAM survey of the 0.4 branch (read only, at 1b50b1ca, 2026-11-12) found:
- **D2 is full** (about 8 B free; ADR 0260, 0263). AXI has about 4.8 KB above its 32 KiB margin, SRAM4 about 700 B, and DTCM is the stack (ADR 0025).
- **ITCM is unused.** It is 64 KB at 0x00000000 and not in `memory.x`. The CPU reaches it at zero wait from code in either bank, under the MPU's default map (PRIVDEFENA, `chimera-board/src/cache.rs`). DMA cannot reach it, and map rows need no DMA. The fault-inject build aims DMA1 at address 0 only to provoke a bus error (`chimera-board/src/fault.rs`), so it never writes there.
- **Today's map state** is `Layers` (`chimera-core/src/ui/midi/layer.rs:58–85`) in `MidiSlot`, in `.ram_d2`. It holds six 16-row layers and a five-section `scratch`, about 2.2 KB together.
- **Per-row runtime state** costs about 55 B a row a Part: the ramp, the bin, the pending turn, pickup's `TakeState` and the echo. It belongs to the Part and cannot be shared. Two limits bound it: `SLOTS <= 64` (the `handed` bitmask is a `u64`, `ui/midi/mod.rs:74`) and `BINDS <= 32` (the echo's `owed` bitmask is a `u32`, `echo.rs:56`).
- **The card path** reads a map into a 702-B buffer on the stack (`midi_map/ctl.rs:262`, and another in `write_side` at 366). `read_small` refuses a longer file, `codec::decode` refuses more than `MAP_LEN` rows (`codec.rs:192`), and `RecordBuf` holds at most 640 B (`storage/record.rs:10`). A 90-row file is about 760 B with 8-B rows, or about 1.12 KB with SysEx's 12-B rows. The console's `put` already takes 4 KiB.
- **MIDI MAP's row index** is a `u8` (`ui/nav.rs:126`, `:756`), which holds 1 + 90 + 16 = 107 rows. The page and the MIDI UI loop over `BINDS`/`SLOTS` in `focus_note`, `hand_in`, `cc_control`, `cc_turns`, `cc_step`, `cc_sysex` and the echo.
- **Flash:** `midi_map::ctl`, `codec` and all of `ui::midi` are bank 2's (`chimera-stm32/build.rs` globs at 238–239 and 303). Bank 2 has about 400 B free, under ADR 0251's 8 KB floor. The owner approved letting bank 1 fall to about 20 KB free (2026-11-12).

## Decision
- **A map is one flat list of at most 90 rows** (`MAP_ROWS`). Its row count is `MapLen` (0..=90) and a row's place is `MapRowIx` (0..90): newtypes, never bare integers. A row is ADR 0217's `Binding` (12 B). As in a Sound's map, a target appears once. There are no sections and no layer merge, and the map is what the Part plays.
- **The factory set ships one map an engine, replacing SUGGEST.** ALGO, MODAL, VA and TAPE (DRUM with the drum engine) are generated by `chimera-utils engine-maps` (`just engine-maps`, formerly `suggest-map`) from the param tables, through the firmware's own save.
  - Each map holds up to 90 rows: ENV 1–2 in both ENV TYPEs (A: ATTACK, DECAY, SUSTAIN, RELEASE; B: RISE, FALL, SHAPE, TIME), the LFOs, the filter, the FX slot and the voice, then the engine's own cells by usefulness, then the rest of its mappable cells in table order.
  - A cell every engine reads sits on the same CC in every map.
  - The rows use CCs MIDI leaves free: those Chimera's MIDI layer passes through (`LearnCc`), less ADR 0263's built-ins and the controls a player's gear sends by itself (1 the wheel, 2 breath, 4 foot, 65–69 the pedals, 84 portamento control). MIDI's undefined CCs go to the cells played most.
  - Every row is absolute `Jump`, as in ADR 0264.
  - The SUGGEST file is no longer shipped. One already on a card still loads, flattened.
- **Rows live in ITCM, six fixed slots of 90 rows, one a Part, plus one staging slot** (`MapSlots`, about 7.6 KB, NOLOAD `.itcm`, written in place at boot). ITCM is declared in `memory.x` from 0x00000400, so no slot sits at or near address 0. The slots are static and never grow. Two Parts on one map each hold a copy. Dedup is not taken: it does not lower the worst case.
- **Runtime state lives in 16 seats a Part, not in the rows.** The 32 binding slots (`BINDS`) become the Sound's 16 rows and 16 seats, each holding a map row by `MapRowIx`. `SLOTS`, `BINDS` and their asserts stay.
  - A map row that hears its control takes a seat if it has none. It takes a resting one: no ramp moving, no bin pending, no turn waiting, not the hand's this pass. Of those it takes the one heard least recently.
  - With no seat at rest, the message is dropped. A seat is never torn from a moving ramp, since a param never snaps.
  - A row that loses its seat starts fresh when it takes another, so an evicted PICKUP row waits for pickup again.
  - Canonical NRPN slots are seated the same way (`PartMidi::seat`).
- **Echo** covers the Sound's rows and the seated map rows, as before. The bursts on a Sound load, a map change and a Part change also walk every map row with ECHO on, one cursor a Part, sending each row's value once as DIN has room. No row keeps a per-row `last`.
- **Lookup is a linear scan** of the Sound's 16 rows and the map's rows for the control: at most 106 compares a message, in the main loop, with no CC index. A Sound row on a control shadows every map row on it. A map row whose target the Part's engine lacks (`Mappable::live`) takes no seat and moves nothing.
- **The file is flat.**
  - The header (kind `Controller`, name), the A/B sides, the generation and the CRC are as ADR 0045 and 0226 say.
  - The body is `MapRows` records (`0x8024`, critical: a reader that does not know it refuses the file, never shows an empty map). Each holds a `Bindings` payload (ADR 0217's version byte and rows, 8 B a row, or 12 B in a record with a SysEx row), each record at most `MAX_RECORD_LEN`. The map's rows are the records' rows in file order.
  - A load streams the chosen side into the staging slot through a sink, checks the CRC and the header's name, and only then copies into the Part's slot. A save streams the records through the store's writer.
  - No map buffer is on the stack (ADR 0025's check).
- **Old sectioned maps (ADR 0226) load flattened.** Their `MapSection` rows are read in file order (shared, then each engine by disk code, as 0.3 wrote them), with no cap a section and the first 90 kept. The rows past 90 count as skipped. So does a duplicate target, which replaces the earlier row in place, as learn does. The next save writes the flat format. `MapSection` is never written again.
- **Saving a Part's rows into its map** (ADR 0226's save) works on the flat list. Each Sound row clears the map's rows on its control or target, then is appended. A save past 90 rows is refused with `MAP FULL`, and nothing is written.
- **Placement.** The flat map's type, file codec and card load and save are a new bank-1 module, `midi_map::flat`, which no bank-2 glob takes, under ADR 0251. `midi_map::ctl`'s sections, layer and absorb code is deleted, with its glob. `ui::midi` stays bank 2's. If bank 2 cannot hold the seat pool, it moves to a bank-1 module (`ui::map_seat`). Each raised budget line names this ADR and ADR 0251.

## Alternatives considered
- **Runtime state for every row** (about 55 B × 90 rows × 6 Parts, about 30 KB, plus the masks past `u64`). No RAM region has room for it, and the hands move only a few controls at once. Seats give the same behaviour to every control actually moving.
- **D2 or AXI for the rows.** D2 is full. AXI has about 4.8 KB above its margin and the rows need about 7.6 KB. ITCM is idle, CPU-only and zero-wait, which is all the rows need.
- **A CC index** (a 128-entry table a Part from control to rows). It saves at most 106 compares a message in the main loop, costs RAM and code, and has to be rebuilt on every edit and load.
- **Dedup, Parts on one map sharing a loaded copy.** It does not lower the worst case (six Parts on six maps), so it saves no RAM that must be reserved. It adds reference counting and a shared edit path. Six copies cost six card reads at most, and an edit reaches the other Parts through the save count (`saves`), as today.
- **Keeping sections, with 90 rows a section.** That is the model the owner replaced: one list, any engine, dim what the engine lacks.
- **Refusing old sectioned maps.** No users depend on them yet, but flattening costs one branch in the record walk and keeps a tester's maps and the old SUGGEST working.

## Consequences
- **D2 gains about 2.2 KB** (`Layers.layers` and `scratch` leave). The seats add about 35 B a Part to `MidiUi`, so the net is about 2 KB free.
- **ITCM's first use.** `memory.x` and `chimera-stm32/build.rs` gain an `ITCM` region and a NOLOAD `.itcm` section, with link-time asserts on its start and size, a host check of the slots' symbol address (`just check-itcm`), and a unit check after merge.
  - Bootloader 1.09 is checked first on the host. Its repo copy (`preenfm3-bootloader-backup.bin`) must hold no reference to ITCMCR (0xE000EF90) and no vector or stack in 0x0000_0000–0x0000_FFFF. Then the application owns ITCM from reset.
  - A future feature that wants ITCM for code (a hot kernel) shares the 64 KB with the slots, about 56 KB left.
- **Bank 1 grows under ADR 0251.** This takes the flat module, the record walk, the streaming sink and writer, and the seat pool if it has to move. Bank 2 shrinks by the sections code. Both are measured in the PR, and the budget lines name this ADR.
- **MIDI MAP shows up to 107 rows**: row 0, the map's rows, then the Sound's. The row index is a typed `PageRow`, and map rows the engine lacks dim.
- **Factory maps** are regenerated from the tables at release (`just release`), and `tools/factory_zip.py` requires the four engine maps. The guide's tables in `docs/guide/MIDI.md` are generated and checked by a test. The private Cirklon `.cki` files are regenerated from the new maps outside this repo.
- **A 0.4 map file is refused by 0.3 firmware** (critical record). A downgrade sees no map, and a save from 0.3 would start the map over.
- **Learned rows still win.** A Sound's 16 own rows shadow the map's on their controls, so learn keeps working on a full factory map.
