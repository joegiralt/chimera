# 0260. Serve USB's configuration from a static past the control buffer; play the host into the main out with explicit feedback

- **Status:** Proposed
- **Deciders:** owner (#885 back in 0.3: "we need all the things"), firmware

## Context
#885 asks for host → device audio, a six-channel capture, OTG DMA, and a control buffer past usb-device 0.3.2's 256 B. Today's configuration is 249 B (ADR 0248, 0256); playback and six channels make it 375 B, and no usb-device feature goes past 256. A configuration past the buffer once stranded the unit (ADR 0222's incident). Bank 2 is full (ORBIT ~352 B free after #936) and D2 has ~8 B, so new code is bank 1's (ADR 0251) and RAM is AXI's (~4.8 KB above ADR 0087's 32-KiB margin on ORBIT). The design note is `docs/superpowers/specs/2026-11-10-usb-audio-followups-design.md`.

## Decision
- **The class answers GET_DESCRIPTOR(configuration) itself** from a 512-B static built once at allocation (`chimera_midi::usb_config::write`), through `ControlIn::accept_with_static`, which usb-device 0.3.2 offers every class before its own handling and sends a packet at a time, cut to wLength. usb-device stays unforked at `control-buffer-256`. The static's bytes for today's shipping (249 B) and bench (217 B) layouts equal what usb-device serves, byte for byte (host test), so the shipping layout moves to the static path first, with no descriptor change, and is flashed alone before any new layout. The largest layout (both streams, six channels, every Part cable: 417 B) is held inside 512 B by a const assert.
- **usb-device 0.3.2 keeps a static reply after its transfer is cut** (`control_pipe.rs`: `static_in_buf` is cleared only when a data stage writes its last byte; `reset`, a new SETUP and a host ending the stage early leave it set), and its next buffered reply then sends the static's bytes: a device descriptor read after a cut configuration read came back as the configuration (`a_configuration_read_cut_short_answers_nothing_else_with_its_bytes`, red before the fix). So the class (`usb_config::Owner`) answers, from the moment a static reply longer than one 8-byte EP0 packet starts until one of a packet ends at once, every standard IN reply usb-device would buffer: the device descriptor, strings 0 to 4, the BOS, GET_STATUS (device, interface, endpoint), GET_CONFIGURATION and GET_INTERFACE, each static and as usb-device would send it, from what the class saw (SET_CONFIGURATION, remote wakeup and endpoint halts set and cleared, bus resets). The host tests hold each answer to usb-device's own, after a cut read and after a reset. Left: usbd-serial's GET_LINE_CODING is answered before the class sees it, so a read cut short right before it would still send stale bytes; no host sends it before a standard request after enumeration. The class answers GET_DESCRIPTOR(configuration) for index 0 only; any other index falls through to usb-device's writer, which serves the 249 B without the playback (harmless: there is one configuration).
- **The shipping layout with playback is 332 B** (`usb_config::duplex`): console 0–1, AudioControl 2 (header listing 3, 4, 5; terminals 1 → 2 capture, 3 → 4 playback), capture 3 (alt 1 stereo 432 B), MIDIStreaming 4 (unchanged), playback 5 (alt 1 stereo, asynchronous OUT 312 B on OUT 3 synced by a 3-byte feedback IN 5, `bRefresh` 2). `bcdDevice` 0x0040. The playback comes after MIDI so MIDI keeps interface 4 and bank 1 allocates the playback after the door's allocation. The full layout (six channels on capture alt 2, 936 B) is 375 B; the owner left the six channels out of 0.3.
- **Playback lands in DAC pair 1 after the master bus**, at SETTINGS › AUDIO ROUTING › USB AUDIO › USB IN (`MidiSettings` param 13, ident `USB_IN`, three bits of the switches byte): `OFF`, −24, −18, −12, −9, −6, −3 and 0 dB, default 0 dB so a host plays as soon as it sends (Elektron's USB TO MAIN, a class-compliant interface's output). Each block eases from the last gain to the step's, and a stream starting fades in from 0. The capture taps the master bus before that sum, so the host never records itself (loopback off, as class-compliant interfaces default). USB IN at 0 dB beside a hot synth can pass full scale: the sum clips cleanly at `to_dac`'s clamp, never wraps. The OUT ring, a dry block and an overflow play silence, never a partial or stale block (`uac_out::play`, `receive`).
- **Every endpoint aimed by frame, never disabled:** once a bus frame (from SOF, unmasked while the playback is on) the servo runs and the OUT and the feedback IN are aimed at the frame now; a packet read aims the OUT at the next frame; a sent feedback is armed again at once. `bench` gains `usb_play on … received … short … overruns … fb … fill …`.
- **The feedback is a PI servo on the OUT ring's fill** (`chimera_midi::uac_out::Feedback`: one pole at 1/32, 1/256 frame a frame plus the error's sum over 256, ±1 frame, 10.14), the ring 512 frames held at `TARGET` 192 (4 ms); the render's `Drain` primes to `TARGET`, plays silence and primes again when dry.
- **Six channels share the capture interface as alt 2**, the input terminal 6 channels with L/R first (wChannelConfig 0x0003, UAC1 § 3.7.2.3), 52 frames a packet so that it, the playback and its feedback fit full speed's periodic budget (1,278 of 1,350 B). Its ring (+8 KB AXI) does not fit beside playback under the 32-KiB margin: it waits for a ruling on ADR 0087's margin or a smaller model-tested ring.
- **No OTG DMA:** DMA mode is the core's, for every endpoint and EP0, so it means forking synopsys-usb-otg under the console and `update`, to save under 0.5 % of the CPU. Taken up only if the unit reads `usb_irq_pct` past 3 % with both streams on.

## Alternatives considered
- **A forked or vendored usb-device with a 512-B buffer.** A crate to carry and reread at each upgrade, and 256 B more in the cell, for what a class hook already allows.
- **Squeezing the layout under 256 B** (7-byte endpoints, no terminals). Non-compliant (ADR 0248), and (a) alone is 332 B anyway.
- **Feedback from a rate count** (SAI frames between SOFs). Needs the DMA's position at SOF and a long window for the 64-frame blocks; the fill servo needs only the ring.
- **A proportional servo alone.** It settles off the target under drift and drains under a steady loss; the model ran dry.
- **`TARGET` 128 for playback.** The model ran dry once a minute with 0.1 % of packets lost; 192 holds the minute and runs at most two dry blocks an hour.
- **Six channels as their own interface with their own terminals.** +31 B and the host could start both captures at once (past the periodic budget); kept as the fallback if Windows refuses a stereo alt under a six-channel terminal.
- **Six channels at 72 frames.** 1,296 B: past full speed's 1,023-B isochronous limit.
- **Playback into the capture as well (loopback).** A DAW monitoring its input would feed back.

## Consequences
- Step 1 (this ADR's PR) adds only host-crate code (`usb_config`, `uac_out`) that no firmware links: bank 1, bank 2, RAM and stack unchanged.
- Step 2 (the same PR): the shipping configuration (249 B, `bcdDevice` 0x0030) is served from the static in every `usb-audio` build, built in bank 1's `Midi::alloc` only if the allocation put the interfaces and endpoints where the layout says (else usb-device writes it, as before); feature `usb-config-writer` (`just firmware-orbit-writer`) builds the old path. Bank 1 +1,288 B `default`, +1,280 `orbit` and `bank2-gate` (measured against the fallback build of the same tree); AXI +512 B.
- Estimated, to be measured: (a) + (d) about 2.4 KB of bank 1 and 4.6 KB of AXI; (b) 0.4 KB and 8 KB.
- The Part cables (ADR 0243) fit beside audio once the static path ships (417 B); turning them on is its own decision (#840).
- Needs the unit: the static path enumerating on Linux with `update` intact; playback for an hour (`short` 0, no out-of-range feedback in dmesg), start/stop and cable pull; macOS and Windows (#841); the feedback endpoint's re-aim cost.
