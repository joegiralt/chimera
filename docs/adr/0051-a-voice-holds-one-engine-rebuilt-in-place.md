# 0051. A voice holds one engine, rebuilt in place

- **Status:** Proposed
- **Deciders:** project owner
- Supersedes [0008](0008-persistent-engine-instances.md) (engines are
  persistent, one instance of each per voice).

## Context
ADR 0008 kept one instance of every engine in each voice because the
alternative it measured, an enum whose new variant is built by value and
moved in, put a 66 KB `ModalEngine` on an unguarded interrupt stack. That
risk was about building by value, not about holding one engine.
`chimera-core/src/in_place.rs` now builds a `repr(C, u8)` enum's variant
where the enum lives (`in_place_enum!`), with no stack temporary. Holding
every engine costs the sum: a `Voice` is 35,248 B, 32,736 B of it Modal, and
Modal 2's exciters need room in D2.

## Decision
A `Voice` holds an `EngineSlot`, a `repr(C, u8)` enum generated by
`in_place_enum!` with one variant per engine (`Algo`, `Modal`). The variant
is the engine: no separate field records which one is active, and every
dispatch is an exhaustive `match` on the slot. The slot is rebuilt in
place, through each engine's field-wise `init_in_place`, when a fade ends or
the VCA's routes end the voice (`Voice::reset` rebuilds into the Sound's
kind) and when an idle voice triggers a different engine. Nothing builds an
engine by value in the audio path. `size_of::<EngineSlot>()` is at most the
largest engine rounded up to the slot's align, plus that align, and a
`Voice` at most `VOICE_CHAIN_BYTES` (2,048 B) plus its slot; both are
asserted.

A switch is a change to the Sound's `SlotKind`, its engine or its Modal
MODE (`SlotKind::of`, which reads those two fields only). It fades that
Part's sounding voices over `Voice::FADE` (128 samples), and each is
rebuilt once silent; a held key restarts on the new kind after the fade.
An idle voice switches at its next note, rebuilt in the same block it
plays. Other Parts and the FX bus are untouched. Knob moves never rebuild.
`Voice::rebuild` is the one path to `EngineSlot::rebuild` and counts it
(`Voice::rebuilds`, wrapping; `reset` keeps it).

## Alternatives considered
- **Keep `Engines`** (one instance of each) — memory is the sum, and it grows
  with every engine and every Modal 2 exciter.
- **A by-value enum** (`*slot = EngineSlot::Modal(ModalEngine::new(..))`) —
  the ADR 0008 hazard: the engine is built on the stack and moved in.
- **A shared buffer pool** — aliasing between voices to manage, and every
  voice still needs its own state for the engine it plays.

## Consequences
Memory is the largest engine, not the sum: a `Voice` is 33,584 B on the
host, and Modal holds only the model it plays (`ModelSlot`, the same
in-place enum). A voice rebuilds at most twice per block: a fade end then
the note that waited for it (a steal across kinds), or an idle trigger then
a VCA-lifetime reset. A MODE edit now fades ringing notes, where it used to
leave them on their old model, or, on a retrigger, rebuild the ringing
model unfaded: a sounding voice of another kind makes `note_on` wait for
the fade. `Voice::held_model_extra` (#183) bills the old model for the
fade's ≤ 2 blocks. Until the 16-bit
strings (spec § 4), a Sympathetic rebuild writes about 31.7 KB, ~2.6 % of
a block. The rebuilds are not billed in `Cost`, as the resets they replace
weren't. The new `unsafe` lives
in `in_place.rs` only: callers pass an in-place constructor, one
`// SAFETY:` line per arm. Each variant's payload is `Sealed`, which only
`in_place.rs` can make, so no code builds a variant by value.
