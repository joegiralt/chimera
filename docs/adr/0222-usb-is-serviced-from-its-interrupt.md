# 0222. Service the USB port from its interrupt; USB MIDI beside the console

- **Status:** Proposed (supersedes in part 0068: "polled, never interrupt-driven")
- **Deciders:** owner ("you're going to be able to drive this yourself", 2026-11-02: a class-compliant USB MIDI device beside the console, no USB host), firmware

## Context
ADR 0068 polls the CDC console from the UI loop. The unit reads `loop_avg_us 641` and `loop_peak_us 40019`, so a polled USB MIDI note could wait 40 ms. A DAW or a USB-only sequencer should play the unit as DIN does, so the port has to be serviced from the `OTG_FS` interrupt. The console carries `update`, the only way testers install firmware, so no interrupt fault may cost it (the USB-audio spike stranded a unit in DFU). Bank 1 is frozen (ADR 0198). The spec is `docs/superpowers/specs/2026-11-02-usb-midi-design.md`; its § 13 rulings override §§ 4–10.

## Decision
- **The device:** `composite_with_iads()` (EF/02/01): the CDC console as before, then a USB MIDI 1.0 function, one cable each way. An in-tree class (about 150 lines, no new crate; `usbd-midi` would bring its own message types and descriptors we don't control): AudioControl and MIDIStreaming interfaces under one IAD (01/00/00), one embedded and one external jack each way, all named "Chimera", two 64-byte bulk endpoints. VID:PID stays 0483:5740; `bcdDevice` 0x0010 → 0x0020; the product string "Chimera console" → "Chimera" (`chimera-usb.py` matches VID:PID and the device node, never the string).
- **The control buffer is 256 B** (usb-device's `control-buffer-256`, enabled on `chimera-midi`'s dependency so every build that links the class, its host test included, gets it). The configuration descriptor is 175 B with MIDI (9 + CDC 66 + MIDI 100) and 75 B without; usb-device's default 128-B buffer drops a GET_DESCRIPTOR it can't fit without a stall, and the host times out. `chimera-midi/tests/usb_class_test.rs` enumerates both layouts through usb-device's own `poll` on a fake bus and checks every descriptor reaches the host. A descriptor change is never flashed without it.
- **One cell, one poll.** `UsbDevice`, the `SerialPort`, USB MIDI (`usb_midi::Midi`) and the handler's state (`Irq`: the guard's, and the `Counts` `stats` reads) live in one static cell, written once by `install` at the end of `connect`, before `OTG_FS` is unmasked at `Priority::MIDI` (USART1's level; audio stays above). Every console build owns the device this way; without `midi-usb` there is no handler, so `with` masks nothing and only the UI polls. `poll_all` is the only poll; the handler and every UI pump (`service`, `UsbOut::pump`, `flush`, `put`, `recv`, the DFU drain) call it. The UI reaches the cell only through `Link::with`, which masks `OTG_FS` in the NVIC (then `dsb`/`isb`) for the closure. `Link` is a token only `install` makes, and `with` borrows it `&mut`, so nesting doesn't compile. Under the mask the UI polls the device itself, so a long answer still moves its bytes. `service` takes one hold a lap: it clears a storm's `held`, copies the counters, polls, flushes and reads the console up to one request. The line parses under that hold, because bytes after a request's newline must stay in the port for the next lap.
- **The storm guard** (`chimera_core::console::shell::{storm, starved}`, host-tested beside `LoopTimer`) trips on either of two tests, checked as the handler enters. It counts entries per 1 ms of DWT cycles (`Cycles`, a `chimera_hal::units` newtype, so cycles and milliseconds can't mix) and trips over `STORM_LIMIT` = 200. It also watches starvation directly: it trips when SysTick's tick (`controls::now_ms`, level 15, which kicks the 100 ms watchdog) hasn't moved for 20 ms of DWT time, or when the UI hasn't held the cell for 250 ms (a lap peaks at 40 ms). The handler stamps the DWT cycle each time it sees the tick change, and every `with` stamps the UI alive, so a long answer (`update`, a 1 MB `get`, `shot`), pumping inside one `service`, counts as alive. Work that holds the UI for seconds with no hold (the loop's card work and SYSTEM sync, the bench's project save, the console's `bank2 install`, `sweep` scan and bench `card`) runs as an errand: `errand(f)` clears the stamp, runs `f` and stamps again. Only the tick test runs meanwhile. A closure scope, so the guard can't be left asleep or forgotten awake. Before the UI's first hold only the tick test can trip, since SysTick starts at boot before `connect`. Three tests on the handler's CPU share failed before this. Its own cycles against a fixed half window never trip above 50 % audio. Its wall cycles against the same half charge an entry the audio's whole-half render (about 1.33 ms) and trip with no storm. Its own cycles against the window less audio's never trip at 65 % load or more on the unit, because `AUDIO_CYCLES` only moves when a render ends, so a storm's windows see no audio at all. A trip masks `OTG_FS`, sets `held` and counts `usb_storms`; `with` leaves it masked while `held`, and the top of the next `service` clears `held`, its hold's unmask letting the handler back: a trip mid-answer stays masked until the next lap's top. A storm costs at most one window's entries per UI lap, and the console runs at the UI's pace, as in 0.2. The known storm is a full console buffer: a CDC packet left at the head of the shared RX FIFO keeps RXFLVL set. synopsys-usb-otg stays at 0.4.0, unvendored. There is no switch to turn the interrupt off; the guard is the fallback.
- **`STORM_LIMIT` stays 200,** read on the unit at dc3a4b92 (the interrupt with the console alone): three `update`s (each pushes the 439 KB `.bk2` through the console) and `get`s under load tripped nothing; an 8 KB no-newline flood under an 8-note DIN chord (7 voices, load 67 %) tripped 128 times, the console answered `status` after, 0 overruns, `usb_irq_pct 1.2`, `usb_irq_us_max 7` (6 idle), `loop_peak` 23.8 ms. § 13.5's 4× rule waits on a dense MIDI stream on the unit, which re-reads `usb_storms` = 0.
- **Long UI work takes an `&Errand`** (`chimera_core::errand`, zero-sized): card work, SYSTEM's sync (and `sync_system_now`), the DFU prompt's sync, `ask_sweep`, `run_install`/`run_erase`, the bench `card` and its project save. Only the board's `errand` scope hands one out in firmware (`Errand::HOST` exists on the host alone), so a long call outside an errand fails to build. While nothing sends USB's out ring (MIDI off this boot, or the door closed since), the poll discards it and its losses, so a door opened mid-run never leaves the UI filling it and pending `OTG_FS` every lap. Port note sources are const-evaluated: USB's where USB MIDI isn't built fails the build.
- **The handler's time is MIDI's.** `OTG_FS` stamps against `AUDIO_CYCLES` as USART1 does, with the same epilogue (`shared::own_cycles`), and adds its own cycles to `MIDI_CYCLES`; the two share a level and never nest, so the card interrupt's own-time stamp already takes USB's out unchanged (§ 13.9). `stats` gains `usb_irq_pct`, `usb_irq_us_max`, `usb_storms`, `usb_midi_in_drops` (event packets from the host dropped) and `usb_midi_out_drops` (echo messages USB's out ring lost, and IN packets the endpoint refused); one `usb_midi_drops` summed three units, so the unit couldn't say which side lost. The shares (`usb_irq_pct`, `card_irq_pct`) divide by a DWT wall clock (`console::WallClock`, folded each lap; SysTick's ms only count its 8.9 s wraps), not by SysTick's ms: a storm stalls SysTick up to the tick test's 20 ms a trip while the handler's cycles run on, and on the unit (4482e138) an 8 KB flood under a 67 %-load chord read `usb_irq_pct 100.0` (127 trips) over the stalled clock. The handler's own-time arithmetic was right and is unchanged; USART1's (`MIDI_CYCLES`, which only the card IRQ's own time reads) too.
- **Bank placement (0175's pattern).** Bank 1 keeps the `OTG_FS` shim, the cell, `with`, `lock`/`unlock`, the guard, the closed path and the MIDI class's `UsbClass` impl as shims. Bank 2 (`usb_midi::door`, in `BoardDoor` as `UsbDoor { alloc, poll }`) allocates the class, polls console and MIDI together, reads, feeds and packs. `alloc` takes USB's note producer and control ring and returns the class with its port (pipe, sinks, IN queue) inside; `poll` takes the device, the console, the class, USB's out ring and the counts. The packets, the IN queue and the Configured edge are `chimera_midi::usb`'s (`InQueue`, `Edge`, `cable_zero`, host-tested in `chimera-midi/tests/usb_test.rs`), globbed into bank 2 whole; `InQueue::new` is `inline(always)`, a habit for anything bank 1 might build. The board's door table grows from 12 to 20 B of its 128-B slot.
  - **A `dyn` vtable's code must be bank 1's.** rustc emits the `dyn UsbClass` vtable as an anonymous constant (`.rodata..Lanon.<hash>.N`) that no `bank2.x` glob can name, so it lands in bank 1 wherever the coercion is. The impl's methods are therefore bank-1 shims (`get_configuration_descriptors` 12 B calling a fn pointer `door::alloc` stores in the class in RAM, `get_string` 24 B, `control_in`/`control_out` 6 B) plus the 60-B vtable. Only `door::poll` lists the class, so the shims run only with the door open. ADRs 0175, 0194 and 0208 kept vtables in bank 1 for the same reason.
  - **New state goes in the cell, not in statics.** The USB counters and `held` are `Irq` fields; Configured (`Edge`), USB MIDI's pipe, sinks and IN queue are the MIDI class's, so the borrow checker proves the poll's exclusion (they were a `static mut` whose exclusion was a comment). The sinks reach the class through `UsbParts` (`usb_midi::Sinks`, filled before the port's first try, as `sweep` is) and `init`; USB's out ring stays beside the class in `Midi`, since a closed door still discards it. As separate atomics in `shared.rs`, LTO churn twice let the machine outliner place a bank-1 fragment tail-calling a bank-2 `Rings::wants` closure, and `door-check` failed `bench-orbit` and `bench-algo,master-tape`. In the cell they pass in every set.
- **Open or closed is a boot snapshot, and a type.** MIDI is configured only if the door was open at `init`; closed, nothing is allocated and the host reads the console alone. `usb_midi::Midi` holds the class, if any, and lets nothing else reach it. Its `poll` goes through the board's door, whose `&BoardDoor` exists only inside its closure. Closed, its poll answers `Polled::Console(Some(Closed))`: MIDI OUT's endpoint address, so bank 1 can poll the console and drain MIDI's OUT, counting the packets in `usb_midi_in_drops` so the shared RX FIFO never blocks (`Polled::ByBank2` when bank 2 polled, `Console(None)` with MIDI off). It can never list the class, whose descriptor shim calls bank 2. A gate build's `bank2 erase` leaves MIDI configured but deaf; a door opened later brings MIDI at the next boot.
- **MIDI in** has its own pipe (`PipeSlot`), source (`shared::source(Port::Usb)`, note source 1; a port's source is its index; `MAX_NOTE_SOURCES` 2 → 3) and control ring (`CtrlPorts::usb`, 512 slots against DIN's 64: a 3,780 B burst of 420 CCs lands between two laps; it costs 3.5 KB of AXI; builds without the MIDI map drop it unread each lap and keep DIN's 64, which holds `bench-algo`'s 8 KiB margin; at 512 its pipe runs straight from the poll in bank 2, since the door's entries take DIN's ring), so running status, SysEx and NRPN state are USB's own. Cable 0 (`Cable::ZERO`; `Cable` is 0 to 15 by construction) is fed one door call a packet; other cables, CIN 0 and 1, and events with no sinks are counted in `usb_midi_in_drops`. Both control rings are one `CtrlPorts` (one static, one take); the UI drains it in one tagged pass with one budget (`CtrlPorts::drain`).
- **Detach lets go.** On a change away from Configured, a bus reset always calls `midi_in::lost` (NotesOff on all 16 channels, then `SensingLost`); a suspend calls it only if USB delivered a note-on since the last `lost` (amends § 13.8), so an idle host's autosuspend doesn't cut a note held from DIN. `lost` releases by channel, not by source.
- **MIDI out.** The out rings are one `OutPorts`, and the door's `out` takes it whole. One out pass runs over a `Tee`: each echo message goes to DIN's ring, then is copied to USB's. DIN keeps its hold-back. USB's copy never holds DIN back: a copy that doesn't fit is lost and counted in `usb_midi_out_drops`, and so is the rest of that pass (its running status would read against the wrong status). Configured is USB's business: the UI always copies, and USB's poll drops what waits while not Configured, its losses uncounted (amends § 13.4: otherwise every boot's first burst reads as drops). Identity is a flag per port; the Reply goes out the port that asked (`Tee::send_to`). The UI pends `OTG_FS` after its out pass; bank 2's poll packs the ring into up to 16 packets and writes them while the endpoint takes them. `WouldBlock` keeps them for the next poll, any other error drops and counts them (`usb_midi_out_drops`); each completed IN packet re-enters the handler. No SOF interrupt.
- **The stack check charges `OTG_FS`** (`tools/stack_depth.py`): `USART1` and `OTG_FS` share a level, so the level is charged the deeper of the two; `UsbDevice::poll`'s pointer calls are charged the deepest linked `UsbClass` method, and the door calls (`poll_all` → `door::poll`, the descriptors shim, `door_feed`, `door_lost`) their named targets.

## Alternatives considered
- **Poll MIDI from the UI loop beside the console.** No ADR, least code, and up to 40 ms of note jitter on the unit's own reading.
- **embassy-usb from the interrupt.** A new stack under the console and `update` for nothing MIDI needs.
- **The whole class in bank 2, the coercion inside bank 2's poll** (§ 13.7 as written). door-check failed: the anonymous vtable sits in bank 1's rodata pointing at bank-2 methods.
- **A guard on entries alone** (§ 13.5 as written). A slow handler under a heavy patch could take the CPU in under 200 entries; the starvation tests close that.
- **A test on the handler's CPU share.** Three formulas failed against how audio's time is counted (see the guard above); starvation is what the guard exists to stop, so it is measured directly.
- **Keep 0.2's CDC-only descriptor when the door is closed.** About 250 B of bank 1 for a second builder; with class EF either way Windows reads the interfaces fresh, so one `bcdDevice` covers both layouts.
- **Count echo skipped before Configured.** Every boot with an echo binding would read drops, and a dense-stream test couldn't use the counter.
- **Always allocate the MIDI class, door open or not.** It removes no closed path: a door closed after boot (a gate build's `bank2 erase`) still needs the OUT drain. A closed boot would also need bank-1 descriptors, since the writer is bank 2's.
- **A loop-top heartbeat as the UI's only sign of life.** Card work would false-trip it; an errand scope keeps the stamp on every hold and sleeps the test only where the UI says it is away.
- **Parse the console's bytes after letting go of the cell.** A stack buffer would lose the bytes after a request's newline, or a line end would end the lap's read and delay a request queued behind `\r\n` a lap; it measured 16 B larger in bank 1 than parsing under the hold.

By symbol (bench-algo,master-tape): `tend_usb` +248, `OTG_FS` +236, `Usb::service` +208, `synth` +192, `poll_all` +164, outliner churn +162, `PerMille::of` outlined +152, `with`/`lock`/`unlock` +84, the class shims +42 and the vtable 60; the rest is the stats strings and churn. By step: the interrupt, cell and guard about +1.0 KB; the class, door and shims about +0.45 KB; USB's pipe and third note source about +0.45 KB (most of it `drain` unrolling one more queue in the block, and `synth`); the tagged drain and out pass about +0.12 KB. The spec's guide is 2 KB a set: bench-algo,master-tape passes it by 48 B. It is a bench set that never ships, the shipped ORBIT build grew 1,728 B, and the owner's rule is no byte-shaving rounds, so it is accepted and every line rose by its measured growth. The guard's starvation tests (the final review's C1) then moved the sets by −72 to +344 B. In default (808,984 B), `Usb::service` grew +184 (`IrqCounts`, 12 B wider, is copied there and `served_at` stored), `synth` +124 (the cell's init), `OTG_FS` +28 and the cell +12. The three sets this took past their lines rose by that measured growth: default +344, orbit +112 and bank2-gate +296. Stamping the UI's alive time at every `with`, inlined at each call site, then moved the sets by −48 to +160 B. The six it took past their lines rose by that measured growth: fault-inject +160, bench-algo, bench-routing, bench-memory and bench-stress +128 each, and bench-orbit +96.

- **The restructure** (simplify-apply items 1–14, base 035825bf; bank 1 measured the same way): default 809,136 → 807,992 (−1,144), orbit −1,288, bank2-gate −960, fault-inject −880, bench-algo −1,120, bench-algo,master-tape −1,240, bench-routing and bench-memory −1,128 each, bench-stress −1,120, bench-orbit −1,296, filter-probes −792, bench-tape 0 (its console now in the cell). Most of it is synth's errand: its closure is emitted out of line, and the card work it holds is no longer inlined twice in `synth`. The rest is one cell hold a service lap, no drop guard, a four-word counter copy, and the out pass and control drain over port tables. Lines that fell are lowered by the measured change. The review's fixes (the `&Errand` proof, USB's out ring discarded while unsent, the DFU restart's sync an errand) then grew the MIDI-USB sets +56 to +120 B (default 807,992 → 808,112: `synth` +80 with the restart's errand closure, `poll_all` +12), and those lines rose by that measured growth; bench-tape fell 48 B. The DWT wall clock then grew the sets +8 to +256 B (default +240), lines raised by it.
- **RAM:** the cell `usb::CORE` is 1,220 B (the 256-B control buffer among it); `shared::OUT` and `shared::CTRL`, each port's ring, sit in `.bss`; builds without `midi-usb` carry USB's rings unused (64 control slots, and 256 B out with `midi-din` + `midi-map`).
- **Stack:** `OTG_FS` 712 B (704 in the bench sets) against USART1's 300 B; nested totals stay under 63,232 B (default 60,020, orbit 60,588, after the restructure).
- **Latency:** a USB note waits for the frame and the handler, not the UI lap. While the console is mid-transfer under the lock, MIDI waits up to one UI lap.
- **Untested on the unit at this writing:** IN packets under `amidi -d`, Linux reading a 64-byte bulk IN with no ZLP, latency and jitter, unplug mid-chord, the closed-door layout, and the storm a large console `put` raises. The unit's verification run (spec § 10) is their check. macOS and Windows are left to testers (private issue #841).
- **The 2026-11-02 incident.** The first composite flash (11b82462) sent a 175-B configuration descriptor through usb-device's default 128-B control buffer. The host timed out reading it, the unit dropped off USB, and the owner had to put it in the bootloader's DFU to recover it. The fix is `control-buffer-256` and the host enumeration test `chimera-midi/tests/usb_class_test.rs`. No descriptor change is flashed without that test passing.
- **The outliner hazard stays.** Any later bank-1 change can bring back a bank-1 fragment calling bank 2; `door-check` catches it.
