# 0259. TUNING picks Scala files by name, and MAPPING lays them on the keys per Part

- **Status:** Proposed (supersedes 0240's card files, slots and unmapped-keys parts)
- **Deciders:** owner (#907, 2026-11-10: parity with stock PreenFM3's Mixer › Scala, files picked by their own name, KEYBOARD/CONTINUOUS per Part; and on review, long file names supported, shown by their long name, scrolling while focused), firmware

## Context
ADR 0240 gave each Part a tuning and read Scala files from eight fixed slots, `TUNE1.SCL` to `TUNE8.SCL`, shown on screen as `TUNE3`. It rejected "a listing of the folder as the choice" (names that move when a file is added, and a dynamic cell format bank 1 lacks) and "unmapped keys silent" (a note-on refusal in bank 1).

Stock PreenFM3 browses up to 128 `.scl` files by name, and maps them per instrument KEYBOARD (the octave rounded up to whole octaves of keys, a 7-note scale starting each octave on C, the spare keys silent) or CONTINUOUS. The owner asked for both (#907). ORBIT's bank 2 has about 2.4 KB free, below ADR 0251's 8 KB line, so the feature may go to bank 1; D2 has about 3.6 KB free.

## Decision
- **The choice.** `PartParams::TUNING` keeps its code and place: `12-TET`, `JUST`, `PYTHAG`, `MEANTONE`, `WERCK`, `MTS`, then one choice `SCALA` (6 on the cell) that plays the Part's Scala file, saved under a fresh disk code, 14. The old `TUNE1`–`TUNE8` disk codes (6–13) are retired: each is a refused code and the Part plays 12-TET. No compatibility past safe.
- **Long names.** Testers copy files in the bootloader's USB disk mode, under any name. The FAT keeps `bohlen-pierce.scl` as `BOHLEN~1.SCL` plus a run of long-name slots. `chimera_fat::dir::Long` reads that run (read-only): UCS-2 to upper case ASCII, `?` for anything else, the first 32 characters (`LONG_MAX`), checked against the short name's checksum. A run whose order or checksum is off, an orphan, or a run not ending on its entry is no name. `Store::list_long` lists each file with it (a store without long names lists them empty). A long name starting `.` (a Mac's `._name`) is never listed. `FileName` takes `~` in TUNINGS and MAPS stems as in the root.
- **What a file shows.** Its long name less `.SCL`, else its stem (`scala_name::shown`). The walk orders by that name; the cell shows its first 7 characters (8 wide ones run into the next cell), and while the TUNING cell has focus a longer one scrolls (`tuning_walk::marquee`: still 1.5 s, a character every 250 ms to the end, still 1.5 s, again, on the UI's 20 fps frame clock). The name of the active Part's file and its description are kept in AXI (`tuning_walk::SHOWN`, atomics), not in the UI's D2.
- **The file is named, not placed.** A project Part keeps its file's stem and the id of the name it shows, `Part::scala` (`ScalaName`: stem of A–Z, 0–9 and `~`, plus `name_id`, FNV-1a of the shown name, never 0). The `Scala` record (`0x0023`, not critical, after the Part's `Origin`) holds the 8 B padded stem then the id, u32 LE. A record of 8 B (before long names) has id 0. Finding the file (`tuning_walk::find`, `rank`): the `.SCL` with the Part's stem and id first (two long names alike in their first 32 characters share an id), then the id alone (a file copied again under `BOHLEN~2`), then the stem alone (renamed, or a project from before long names). The `.KBM` that pairs is the one showing the same name (`bohlen-pierce.kbm`). A name the firmware can't hold reads as none. The Part's field is `ScalaName::NONE` for none, not an `Option`: no tag byte a Part. Only with `tuning` (the bench builds' D2 is full).
- **The page.** SETTINGS › AUDIO ROUTING › TUNING: A TUNE, B TUNING, C MAPPING.
  - Turning TUNING past `MTS` walks the card's `/CHIMERA/TUNINGS` `.SCL` files in the order of the names they show, stopping at the last; turning back past the first returns to `MTS`. With no files it stops at `MTS`. The focus band's line shows the `.scl` description (its first line that isn't a comment), upper case, 30 characters, or `<STEM>.SCL` when blank, `NO FILE PICKED` on SCALA without one.
  - The first 128 `.SCL` files in folder order are reached (`MAX_FILES`, stock's cap), and a read passes at most 256 files of any kind: a detent costs a bounded folder read however many files the card holds (a 5,000-file archive with a Mac's twins: 80 blocks a read, against 2,525 for the whole folder). Turning up past the last file reached when there are more says `FIRST 128 FILES ONLY`. No listing is kept. The turn's detents are counted in bank 1 (`Tuned::turn`); the next card pass reads the folder once a file detent and moves (`ui::tuning_walk::turn`). The current file's place comes from `SHOWN` without a read.
  - A Mac leaves `._NAME.SCL` and `.DS_Store` (#930). The FAT listing skips hidden-attribute entries (`Entry::hidden`). Short names holding `_` are refused by `FileName`, and long names starting `.` are skipped. `list_stems` (MIDI MAP's controller list) takes the extensions it lists (`.A`/`.B`). A hidden file is still found by name, so a write never makes a second entry of its name. A controller map copied with a long name now lists too (its `~` stem), shown by the name inside it as before.
- **MAPPING** (`PartParams::MAPPING`, id 12, disk ident `MAPPING`): `CONTIN.` (continuous, 0, the default: ADR 0240's no-`.kbm` layout) and `KEYBD` (keyboard, 1). Full words don't fit the cell; the guide spells them out, `KEYBD` as the filter's.
  - KEYBOARD is a `Keymap` (`Keymap::keyboard`): its size the scale's steps rounded up to a multiple of 12, degree 0 on middle C at 12-TET's pitch, the period the scale's own, the keys past the degrees unmapped.
  - A `.KBM` of the same stem wins over MAPPING; the band on MAPPING says `<STEM>.KBM MAPS THE KEYS`. On a built-in or MTS it says `FOR SCALA FILES`.
- **Silent keys.** `offsets_into` returns its unmapped keys; with KEYBOARD they are written as each Part's silent mask (`Tunings::silence`, 16 B a Part beside the tables) and a note-on on one is refused (`Instrument`, after the snap: `tuning::silent`). A `.KBM`'s `x` keys stay 12-TET as in 0240. A HELD RE-SNAP onto a silent key keeps sounding at 12-TET.
- **Over USB.** The console's `put` takes `/CHIMERA/TUNINGS/<stem>.SCL|KBM`, any valid 8.3 stem without `~`, any case; a `.SCL` still drops its stem's old `.KBM`. The console's `rm` takes the same paths and a `~` short name (one parse, `put::tuning`; `put` refuses any path with `~`). `chimera-usb.py tuning <file.scl> [<file.kbm>]` puts both under the `.scl`'s own stem, upper-cased, and refuses a name that isn't 1–8 of A–Z and 0–9 with a message to rename it.
- **Applying** stays pulled (0240): each Part's applied TUNING, MAPPING and file are kept as one 32-bit key (`Tuned::keys`: the index for a built-in, FNV-1a of the rest for a file); a `put` reads every Part on a file again. The active Part's file is read again when the description held is another file's.
- **Placement.** Bank 2: apply, description and band words (`ui::tuning`), `Keymap::keyboard` and the description reader (`chimera_theory::tuning`). Bank 1 (ADR 0251, each budget line naming this ADR): the walk, the finder, `SHOWN` and the marquee (`ui::tuning_walk`: in bank 2 ORBIT's overflowed by 544 B), `ScalaName` (`chimera_engine::scala_name`, out of `tuning`'s bank-2 section: bank 1 calls it and its derives), the FAT long-name reader, the MAPPING param's data, the `Scala` record and `Part::scala`, the turn's detent count, the cell's stem, the band call (`UiDoor::tuning_note` takes the `Tuned`, the param and the Part, and returns a `Line`; the door's magic is `0xB2C0_0257`), the note-on refusal and silent read, and the console's stem parse.

## Alternatives considered
- **A FILE choice plus a SCALE cell listing files.** Two cells for one decision, and a SCALE cell inert on six of seven choices. Stock's list follows its enable switch; one list past MTS is one turn.
- **Show the description in the cell.** Descriptions run to 40+ characters; the cell holds 8. The stem in the cell, the description on the band's line.
- **A listing kept in RAM, or no cap.** A sorted index of every file: 60 KB for 5,000, more than AXI has. No cap: a detent reads the whole folder, 1–2 s of a stalled UI on a full archive.
- **Save the long name's text in the project.** Up to 32 B more a Part, in the UI's D2 (bench-algo has 8 B). The id finds the same file, and the name shown comes off the card. Two files whose shown names share an id (alike for 32 characters, or a 2^-32 hash clash) are told apart by stem.
- **Rename to 8 characters (the first review's docs).** Testers don't have the tool, and every Scala archive file has a long name.
- **Silence as NaN in the table.** Every reader of the table (strike, glide, re-snap) would need the check; a mask read once at note-on is one place.
- **Sorting the listing.** A core sort in bank 2; picking the nearest name above or below the current one in one pass does the same with no sort.

## Consequences
- Any number of Scala archive files can sit on the card under their own names, long ones included; a project keeps playing its file when others are added, or when it is copied again.
- An old project on `TUNE1`–`TUNE8` plays 12-TET (no users yet).
- A `.bk2` from before reads the TUNING band as closed until updated (the door's magic moved; one-step install pairs them).
- **D2.** The UI's `Tuned` (applied keys, `.KBM` bits, the file last read) holds only the turn without `tuning`: the bench builds keep their D2. The description and shown name live in AXI.
- The marquee's phase is the UI frame clock's, not the moment focus landed: a name may start scrolling part way.
- **Measured** against main ae687093: see the PR (`tools/bank1-budget.txt` lines name this ADR).
