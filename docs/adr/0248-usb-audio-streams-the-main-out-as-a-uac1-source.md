# 0248. Stream the main out to the host as a UAC1 asynchronous source in USB MIDI's function

- **Status:** Proposed
- **Deciders:** owner (#847: "USB audio (stretch): class-compliant audio alongside MIDI and the console"), firmware

## Context
#847 asks for class-compliant USB audio beside the CDC console and USB MIDI (ADR 0222). The 2026-10-25 spike (local branch `usb-audio-spike`, (private notes)) ran UAC1 stereo 48 kHz 24-bit both ways under PipeWire at 5.8 % CPU, worst entry 43 µs, but it also hit four problems. Its bank 1 grew 7.4 KB. It vendored synopsys-usb-otg for the isochronous even/odd frame fix. It squeezed the configuration under usb-device's 256-B control buffer with non-compliant 7-byte audio endpoint descriptors. Its endpoint disable plus FIFO flush, spinning inside the interrupt, got the port disabled by the hub, and the unit had to be recovered through DFU. ADR 0222 has since moved the console and MIDI onto `OTG_FS` at MIDI's level, with the storm guard and the RXFLVL park. usb-device 0.3.2's control buffer tops out at 256 B (`control-buffer-256`), and the console-plus-MIDI configuration is already 175 B. The unit is away, so this work ships off by default and must prove everything it can on the host.

## Decision
- **UAC1, device → host only, the main out.** Stereo 48 kHz 24-bit (3-byte subframes) PCM: DAC pair 1, the main stereo out of the master bus (`chimera-product-architecture.md`). The samples are the DAC's own `to_dac` words, so the host records exactly what the jacks play. UAC1 is driverless on Linux, macOS and Windows. UAC2 adds nothing at full speed, plus a clock model that Windows' driver limits. The issue's comments don't ask for it.
- **One Audio function.** The stream's AudioStreaming interface joins USB MIDI's function. One AudioControl header lists the stream and MIDIStreaming (`bInCollection` 2), under one IAD over three interfaces (AudioControl, stream, MIDIStreaming), as the MIDI class spec's Audio function does. AudioControl's chain is the header (10 B), one input terminal (a line connector, 0x0603, stereo L/R) and one output terminal (USB streaming, 0x0101). The stream has alt 0 with no endpoint and alt 1 with AS general (a 1-frame delay, PCM), Type I format (one discrete rate) and UAC1's 9-byte isochronous endpoint plus its class-specific endpoint (no controls). The configuration is **249 B, 7 B under the 256-B buffer**. A separate audio IAD and AudioControl would be 274 B, which no usb-device feature fits. `bcdDevice` is 0x0030, a new layout under the same VID:PID that Windows caches drivers by. `chimera-midi/tests/usb_class_test.rs` enumerates it through usb-device on the fake bus and parses it whole: its length is held to the byte, and the test checks the IADs, every interface and alt setting with its endpoint count, the AudioControl total, the terminal links, the format, the endpoint's type, size, interval and sync, unique endpoint addresses, and SET/GET_INTERFACE through the device (alt 1 taken, alt 2 stalled).
- **An asynchronous source, no feedback endpoint.** The SAI clock (a PLL off the HSE crystal) is the master, and each packet carries what that clock made (USB 2.0 § 5.12.4.1). The host needs no feedback for capture, since explicit feedback is a sink's. An adaptive source would have to resample to SOF, and a synchronous one would need the SAI locked to SOF; both rejected. `chimera_midi::uac::Pacer` sizes each packet:
  - Before the first packet it waits for the ring to hold `TARGET` (128 frames, about 2.7 ms).
  - Each packet carries 48 frames per bus frame since the last one, trimmed by the smoothed fill's error over 8 (one pole at 1/32, a ±8-frame dead band). At ±100 ppm of drift that makes a 49 or a 47 every few hundred packets.
  - Past `HIGH` (384 frames: the host stopped reading with the stream on), the ring drops back to `TARGET`, counted as `resyncs`.
  - A ring that runs dry sends what it has, counted as `short`, and primes again.
  - wMaxPacketSize is 576 B (96 frames), so a frame the interrupt was late for is made up in the next packet. The audio interrupt holds `OTG_FS` off for its whole render. In the host model, a heavy render (60–95 % of a block) makes about 9 % of frames late. With a 49-frame cap, even a 50–75 % render resyncs four times a minute. With 96 the model runs clean.
- **The parity, never a disable.** synopsys-usb-otg 0.4.0's `write` sets no even/odd frame bit, and the core sends an isochronous packet only in a frame of the parity it holds. Before each `write`, the pump writes DIEPCTL's SODDFRM or SEVNFRM for the frame after the one in progress (`uac::aim`, every other bit as read, no action bit). On the incomplete-isochronous-IN interrupt, a packet still armed is aimed again the same way: by the frame now, not by toggling its old parity, which the spike found never catches up. The crate stays unvendored. The endpoint is never disabled or flushed. A packet the host never took stays armed until the host polls in its parity, so a stream stopped and restarted may begin with one stale millisecond.
- **The interrupt's extra entries only while streaming.** SOF (the pump's heartbeat) and the incomplete IN interrupt are unmasked when the host sets alt 1 on a Configured device. They are masked when it sets alt 0, on a bus reset, or on deconfiguration, so an idle stream costs no entries. The pump writes GINTMSK with `rx_park`'s read-modify-write under the same exclusion: in the handler or under `with`'s mask. A closed door masks both bits from bank 1 (`usb_audio::closed`, in `Closed::drain`), because bank 1's poll never clears their flags. Each entry pumps if no packet is armed: at SOF, at the last packet's completion, and at any other entry.
- **The ring.** `chimera_midi::uac_link::Ring<512>` is a single-producer, single-consumer ring of stereo DAC words. Its slots are atomics, so it needs no `unsafe`, and on the M7 a relaxed load or store is a plain one. The audio interrupt pushes a 64-frame block all or nothing (`render_half` → `usb_out`, inlined), so a ring the host isn't reading refuses it whole. The USB interrupt pops a packet at a time. It sits in cached AXI SRAM (4 KB of `.bss`), and the push reads the cached float block, not the uncached DMA half.
- **Bank placement (0222's pattern).** Bank 2, through USB MIDI's existing door poll (`usb_audio::door`, `chimera_midi::uac`, globbed in `build.rs`), holds the stream's allocation, the interrupt events, the pump and the descriptors. Bank 1 holds the ring the audio interrupt pushes, the class's three alt-setting shims (`get_alt_setting`, `set_alt_setting`, `reset` on `MidiClass`'s bank-1 vtable, using `uac_link::Alt`), `closed`, and the `bench` line. `check-door-placed` checks whatever of the stream is left out of line.
- **Off by default.** The feature is `usb-audio` (chimera-stm32 and chimera-board; it implies `midi-usb`). `just check` builds it, door-checks it and places it; `just clippy` lints it; `just stack-check` charges it. The `bench` request answers `usb_audio on … sent … missed … short … resyncs … reaimed … fill …` for the unit's run.

## Alternatives considered
- **UAC2.** No bandwidth at full speed, plus a clock entity model. Windows' usbaudio2.sys limits shared clocks and implicit feedback, and Linux needs a clock selector before it starts a feedback endpoint (the research notes).
- **Its own IAD and AudioControl beside MIDI's.** 274 B, past the largest control buffer usb-device offers. Patching usb-device for 512 B would change every build's RAM and the console's own stack for a layout choice.
- **7-byte endpoint descriptors (the spike).** They fit, but they aren't UAC1's descriptor, and a strict host (Windows) may refuse them.
- **Vendoring synopsys-usb-otg with the parity fix (the spike).** 15 k lines to carry, against two register writes around the crate's own `write`.
- **Disable and flush the endpoint on an incomplete IN or a stop (the spike's f16cec8c).** It spun in the interrupt, and the hub disabled the port. Re-aiming needs no wait.
- **A 47/48/49 packet (wMaxPacketSize 294).** The model shows renders past half a block resyncing several times a minute.
- **USB above audio.** It makes every console and MIDI entry preempt the render (up to 43 µs) and changes ADR 0222's time accounting. Arming the next packet as the last one completes gives a frame of slack instead.
- **OTG DMA.** It would cut the FIFO writes (about 72 words a packet), but whether it works on H750's OTG2 is unverified (the spike's notes). Left for later.
- **The three pairs summed, as the desktop's speakers hear them.** Pairs 2 and 3 are individual outs that bypass the master. A 6-channel alternate setting is the way to carry them later.
- **16-bit samples.** About a third fewer FIFO words, but it throws away the DAC's resolution.
- **On by default now.** Nothing in this PR is proven on the unit.

## Consequences
- **Cost (host-measured or static; the unit's run is the check).** The audio interrupt's push is about 26 instructions a frame, about 1.7 k a block, about 0.3 % of a 1.33-ms block at 480 MHz (counted on the `usb-audio` ELF). The USB interrupt adds a packet's FIFO writes and a poll each millisecond while streaming. The spike read 5.8 % with both directions. One direction is expected at roughly half that, and `usb_irq_pct` reads it. RAM with the feature: `.bss` +4,728 B (the 4,104-B ring, the 576-B packet buffer and the stream's state in the cell). Bank 1 (rebased on 754a642b): `default` 814,484 B, none of it linked without the feature. `usb-audio` 815,636 B, +1,152 over `default` (the ring push in `render_half`, the three alt shims, `closed`, the `bench` line and its formatting), held to its own line in `tools/bank1-budget.txt`. Stack: `OTG_FS` 832 → 864 B, nested 60,188 → 60,220 B of 63,232 (clean builds of d6fc1d0c's tree).
- **Control buffer.** 7 B are left. Another function, or a larger AudioControl (a feature unit for volume, a second terminal), needs usb-device's buffer patched past 256 or a reshaped layout. The test holds the size to the byte, so that is a decision, never drift.
- **Latency.** About `TARGET` (2.7 ms) plus a packet, device side.
- **Needs the unit** before the feature turns on: enumeration on Linux, macOS and Windows; a glitch-free capture (`bench`'s `short` and `resyncs` at 0, a sine recorded without a click); drift over an hour (`resyncs` 0, `missed` made up); `usb_irq_pct` while streaming; `arecord` started and stopped alone, many times (the spike's wall), and a cable pulled mid-stream.
- **Follow-ups:** the host → device direction (OUT plus explicit feedback); a 6-channel alt setting for the three pairs; OTG DMA to cut the FIFO writes; the 512-B control buffer if the layout must grow.
