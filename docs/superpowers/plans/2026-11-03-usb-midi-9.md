# USB MIDI to 9/10 Implementation Plan

**Goal:** Raise PR #844's merged USB MIDI to ≥ 9/10 on every review dimension (fresh review: Q7 E8 P7 Pr7 C7).

**Architecture:** Fix the storm at its root (mask RXFLVL while a console packet waits for the UI), move USB MIDI's stateful queue and Configured edge into host-tested `chimera-midi`, tighten the types the review flagged, cut the per-byte and per-lap holds.

**Tech Stack:** Rust no_std, STM32H750, usb-device 0.3.2, synopsys-usb-otg 0.4.0, usbd-serial 0.2.2.

**Spec:** `docs/superpowers/plans/2026-11-03-usb-midi-9-review.md` (the fresh review: findings I1, I2, M1–M10 and "What would raise each score to 9"). Background: `docs/superpowers/specs/2026-11-02-usb-midi-design.md` (§ 13), `docs/adr/0222-usb-is-serviced-from-its-interrupt.md` (Proposed, so it is edited in place).

## Global Constraints

- Bank 1 is frozen (ADR 0198): new code goes to bank 2 or core called only from bank 2; `door-check` must pass; any bank-1 line in `tools/bank1-budget.txt` moves only by measured change on a clean tree, with a comment naming ADR 0222. Bank 1 should not grow overall.
- DIN bytes on the wire and audio stay identical; goldens bit-identical.
- `chimera-midi/tests/usb_class_test.rs` must pass; no USB descriptor change.
- No `unsafe` without `// SAFETY:`. No heap. Builds `nice -n 15`, `CARGO_BUILD_JOBS=10`. Targeted tests per task; `just check` before the PR.
- Commits: no type prefixes, terse, never stage `chimera.bin`.
- Stats line names already used (`usb_storms`, `usb_midi_drops`) may change; `tools/chimera-usb.py` doesn't parse them.

## Review Focus

- A console flood while TAPE streams under a heavy chord: `stream_underruns` stays 0, encoders don't skip.
- `update` (439 KB through the console) still works ×2 with no trips caused by the new RXFLVL mask.
- A bus reset in the middle of a dense USB note burst still releases every note.
- A USB note played and released, then host autosuspend, while a DIN chord is held: the DIN chord holds.
- Bank 2 closed: console only, `update` works (the RXFLVL mask must also be lifted on the closed path).

And for `Edge` (Configured tracking): returns `Some(Left::Reset)` / `Some(Left::Suspend)` exactly on the transitions `door::poll` uses today, `None` otherwise. ### Task 3: The storm fixed at its root (I1, M7, M8)

**Files:** `chimera-board/src/usb.rs`, `chimera-core/src/console/shell.rs`, `chimera-core/tests/console_shell_test.rs`, `chimera-core/src/console/answer.rs`, ADR 0222.

Facts: synopsys-usb-otg 0.4.0 writes `GINTMSK` only in `enable()` (`bus.rs:502`); `poll` reads `GINTSTS.RXFLVL` and leaves a packet at the FIFO head when no class reads it (CDC buffer full), so RXFLVL stays set and the handler re-enters.

- [ ] In the `OTG_FS` handler, after the poll and class reads: if `GINTSTS.RXFLVL` is still set, clear `GINTMSK.RXFLVLM` (the packet waits for the UI). `Usb::service`, after draining the serial port, sets `RXFLVLM` again — on the open and the closed-door path. Only this file touches `GINTMSK` after enable; say so in a SAFETY/comment and ADR 0222.
- [ ] The guard stays as a backstop: `TICK_STALL_MS` 20 → 6 (SysTick steps every 2 ms; 3× margin), entries/ms unchanged. Count trips per test: `usb_storms` stays the total; add `usb_storm_kinds <entries> <tick> <ui>` and `usb_rx_parks <n>` (RXFLVL mask events). M7: saturate or comment `alive` past the DWT wrap, as `tick_at` is. M8: file a GH issue for § 13.5's 4× rule unless Task 5's measurement settles it, and reference it from `STORM_LIMIT`.
- [ ] Host tests for any pure decision added (e.g. a `park(rxflvl_after) -> bool` or the per-kind counter).
- [ ] ADR 0222: replace "a storm costs at most one window's entries per UI lap" with what is now true; record the RXFLVL park as the root fix and the guard as a backstop.
- [ ] Commit.
