**Goal:** ORBIT plays on the desktop: five Euclidean rings over a chord ring, snapped, mutating, with its pages, transport and its place in the navigation (Slice 1, "sounds good 10 seconds after PLAY"), then VOICE, NOTES, STEP rings, scenes, SETTINGS › ORBIT, capture, live snapping, MIDI clock and saving in the project file (Slice 2). The firmware builds it behind the `orbit` feature, off by default.

**Architecture:**
- **Functional core:** `chimera-theory` (merged, PR #246) and `chimera-core::orbit`. The rings, walks, MUTATE and dice are built (Built already, below). This plan adds the chord ring, the clock's maths, the scene and `block()`: pure functions of state, settings and a span of samples.
- **Audio shell:** `orbit::runner::OrbitRunner`, in core, owned by each shell's audio engine. Per 64-sample block, after `LoadGate::before_block`, it reads `AudioShared.orbit`, steps the clock, calls `block`, and hands each event to `Instrument::handle` with a `NoteOrigin`.
- **Navigation:** `ui::nav` gains `Loc::Orbit(OrbitAt)`, `Recall.orbit` and `Recall.orbit_from`. Keys in ORBIT are their own type (`OrbitKey`), so a ladder key can't reach ORBIT and an ORBIT key can't jump to a Part.
- **UI:** `ORBIT_CHAIN` (ORB, RING, CHRD, SCN) in `ui::orbit`, drawn by the page renderer through `Location::page`. The scene lives in the `Project`. The engine reports back through an `OrbitView` triple buffer.

**Tech Stack:** Rust 2024, `no_std` core, `chimera-theory`, no new dependency. `just check`, `just test`, `just desktop`, `just firmware`.

**Spec:** `docs/superpowers/specs/2026-09-30-orbit-design.md` (owner-approved; § 7 amended 2026-10-02 for the navigation, listed below). Navigation: ADR 0044 and ADR 0066 (both Proposed, on `nav-core`), `docs/superpowers/specs/2026-10-01-settings-menu-design.md`. The built core: `chimera-core/src/orbit/`, `chimera-core/tests/orbit_core_test.rs`.

## Global Constraints
- **Pure core** (spec § Principles). `chimera-theory` and `chimera-core::orbit` take no time source but their arguments. The shells are thin.
- **Types decide what's possible** (ADR 0012; owner: "if we could solve an imperative problem using the type system, we absolutely should"). `RingIdx`, `Steps`, `Fill`, `Pool`, `Pct`, `Octave`, `Bars`, `Segs`, `Bpm`, `SceneIdx` and the rest are checked newtypes or enums. The navigation follows nav-core's seals:
  - `PageAt` is made only by a chain, so an `OrbitAt` page is one of `ORBIT_CHAIN`'s;
  - `ORBIT_CHAIN`'s home is declared with `ChainDef2::with_home_def(&ORBIT_ORB)`, checked at compile time;
  - `Outside` can hold neither `Settings` nor `Orbit`, so neither way back can loop;
  - keys inside ORBIT are an `OrbitKey`, which has no Part jump and no SEQ hold;
  - a scene overwrite or clear takes a `Said<SceneSlot>`, which only a prompt's confirming pill makes.
- **The audio thread never allocates or blocks.** `Events` is a fixed array of `EVENTS_PER_RING` = 2 per ring (one off, one on). That size holds for the worst case because a window never holds two step boundaries of one ring (Timing, below).
- **Parts can't tell ORBIT from a keyboard.** ORBIT's notes enter `Instrument::handle` and take voices by the allocator's rules, with no priority and no reserved voices (§ 9).
- **Deterministic.** Every draw comes from a ring's own seeded `Rng` (§ 2.2, choice 10). The same scene from the same Start gives the same events, sample for sample.
- **Never snap the UI** (CLAUDE.md). The ORB sweep and dot flashes animate from the reported position, in `UiState::update(UiTick)`, which a `Pacer` hands out at `UI_FPS` = 20. Tests step it with `UiTick::for_test()`.
- **Timing** (§ 6.2):
  - a bar is four beats, 96 MIDI clocks;
  - the position is `(bar: u32, phase: u32)`, with phase in units of 2⁻³² of a bar;
  - a block fires the steps in `[t − 32, t + 32)` around its start sample `t`;
  - **the windows are contiguous.** Each block's `from` is the previous block's `to`, and Start begins at `Position::ZERO`. A tempo change re-anchors the clock at that same edge;
  - **the advance per block is capped** at what `MAX_BPM_EXT` = 1,200 BPM moves in 64 samples, which is 1/150 of a bar, less than the 1/32 of a bar a 32-step ring's step spans. So a window holds at most one step boundary per ring, under either clock. A MIDI clock that jumps ahead is caught up over the following blocks, never skipped over.
- **Hold:** nav-core's `ui::hold::HOLD_MS` = 500, shared by MENU, SEQ and B*n*. A tap acts on release; a hold fires once at `HOLD_MS`, and its release does nothing. Gates read `Controls::edges` and `now_ms`, so no press is lost in a stalled frame.
- **Ranges** (§ Design choices): STEPS 1–32, SEGS 1–8, BARS 1–8, OCTAVE 0–8 (C4 = 60), BPM 30–300 in steps of 1 (default 120), ACCENT_BOOST +30 capped at 127, `RESNAP_GLIDE_MS` = 40.
- **Memory:** `size_of::<OrbitRunner>() <= 1024`, asserted at compile time. The runner stores no second scene. Every new AXI static is counted in `AXI_RESIDENT`. (pre-flight) Main uses 433,700 B of AXI's 524,288, and `AXI_SRAM − AXI_RESIDENT >= 64 KB` is asserted, so ORBIT has about 25 KB (23.5 KB after `usb-console`'s 1.5 KB). Estimated: `Scene` ≈ 390 B (`Ring` is 64 B), `OrbitSong` ≈ 3.6 KB with nine scenes, `AudioShared` ×3 +1.2 KB, `TripleBuffer<OrbitView>` ≈ 1 KB, `OrbitRunner` ≈ 0.7 KB: about 6.5 KB. `UiState` without its `Project` is 3,592 B against a 4,096 B guard (`ui_state_fits_the_ui_reserve`), so `OrbitUi` holds a compact status, never a whole `OrbitView` (Task 7).
- **Storage** (ADR 0045): codes are frozen and append-only, and every enum has an exhaustive `DiskCode` table pinned in `tests/fixtures/disk_codes_v1.txt`. ORBIT's records are non-critical, and each is under `MAX_RECORD_LEN` = 512.
- **BlockDef ids** are unique (`binding_test::block_def_ids_are_unique`). ORBIT's take the next free ones, 78 on: ORB 78, RHYTHM 79, CHRD 80, CUSTOM 81, VOICE 82, NOTES 83, SCN 84, the SNAP leaf 85. If main has moved, take the next free and keep the order.
- **Firmware:** the `orbit` cargo feature of `chimera-stm32`, off by default. `just firmware` builds with and without it, and from Task 19 `just check` does too. (pre-flight) Whether ORBIT is reachable is decided at compile time, not by a runtime flag: `chimera-core` gains an `orbit` feature, **on in its `default`** (so `just test` and the desktop cover it), and `chimera-stm32` depends on `chimera-core` with `default-features = false` and forwards `orbit = ["chimera-core/orbit"]`. The feature gates only SEQ hold's `NavKey::SeqHold`, SETTINGS' ORBIT row (a `const` kind: `List(&ORBIT)` or `Later(issue(262))`) and `Screen::SceneSaveTo`; the firmware's own `orbit` also gates the runner and PB1's drive. There is no `set_orbit_enabled`. Task 21 flashes it for Claude's on-unit QA; the ship flash is the owner's call.
- **Repo rules:**
  - every `unsafe` has a `// SAFETY:` comment; no libc, no heap on the audio path;
  - decisions that constrain later work get an ADR in `docs/adr/`, listed in its README; never edit an accepted ADR (0044 and 0066 are Proposed, and are amended in place, each change marked);
  - bugs and follow-ups go in GitHub issues (joegiralt/chimera), referenced by URL.
- **Commits:**
  - a terse plain sentence, with no type prefix;
  - files are staged by name, or by the source directories each task lists (`chimera-core/src`, `chimera-core/tests`, `chimera-desktop/src`, `chimera-stm32/src`, `chimera-hal/src`), none of which holds `chimera.bin` or the UX spec;
  - run `git status` first. **Never stage `docs/chimera-ui-ux-spec.md` or `chimera.bin`.**
- `just check` passes before every commit. No task ends red.
- **QA before UAT:** Claude runs each slice's desktop QA gate (tests, the parameter sweep with ORBIT's parameters in it, the scripted ORBIT render, the screen atlas). The owner only judges by ear, from the UAT list.

## Review Focus
These are the inputs the spec implies but no spec test exercises, most likely to bite first. Each one's test is in the task named.

1. **A gate shorter than a block**, such as GATE 0 %, or 1 % at 300 BPM on 32 steps. The off would be scheduled inside the block that sends its on. Offs go out before ons, so the voice would stick. Every off lands at least one block after its on. Task 3: `gate_zero_never_sticks`.
2. **BPM turned while playing.** A window computed afresh at the new tempo would overlap the last one (steps fire twice) or leave a gap (steps skipped). The windows stay contiguous. Task 2: `bpm_change_keeps_the_position`; Task 3: `set_bpm_keeps_windows_contiguous`, `bpm_sweep_fires_every_step_once`.
3. **A Part's CHANNEL or a ring's TARGET changed while a note is held.** The off must go to the channel the on went to, or the voice sticks. Task 3: `pending_off_keeps_its_channel`.
4. **Two rings on one Part playing the same note.** One ring's gate must not release the other's voice, even under Mono. So `NoteOrigin::Orbit` carries the ring. Task 4: `two_rings_on_one_note_release_their_own`.
5. **STEPS cut, or a ring muted, while its note is held.** For example, STEPS 13 → 5 at step 12. The pending off still fires on time. Task 3: `edits_mid_gate_never_strand_a_note`.
6. **A B*n* press that starts with MIX down and ends after MIX is up.** It must stay a mute: no ring tap on release, no crossing at `HOLD_MS`. nav-core's gate keeps `muted` for the whole press. Task 6: `mix_b_is_only_a_mute`.
7. **MENU hold in ORBIT while a scene switch is queued.** The quick save writes `live`, which is then the queued scene. Task 18: `quick_save_while_queued_saves_the_landing`.

## Decisions this plan makes where the spec is silent or ambiguous
Each of these that departs from the spec's text is written into the spec, marked "(amended 2026-09-30: plan)", "(amended 2026-09-30, controller ruling)" or "(amended 2026-10-02: navigation)", in the plan's own commit.

**Storage**
- **Record tags.** The spec's 0x0007–0x000C collide with projects-core, which takes 0x8007–0x000A (by the low 15 bits) and keeps 0x0B–0x0F for its reserved records. The ORBIT records take:
  - `Tempo` = 0x000B, the tempo slot the projects spec reserves. Its payload is § 8's `f32`, decoded by rounding and clamping to `Bpm`; a NaN takes the default.
  - `OrbitBlock` 0x0010, `OrbitNotes` 0x0011, `OrbitChord` 0x0012, `Orbit` 0x0013, `OrbitScale` 0x0014.
- **`OrbitChord` holds exact tones** (controller ruling). Chords are exact tones with smart labels, as the owner decided, and a captured cluster names no `Quality`. The payload is:
  - `scene u8, seg u8, degree u8, played u8` (0 none, 1 played), `bass pc u8`, `tones u16 LE` (bit n = pitch class n).
  - A played chord is always `from_notes`'s, built on its bass. So it decodes as `Chord::from_notes` of the bass note followed by its other tones above it, and it round-trips under `Eq` (tones and bass).
  - A set missing its bass, or with fewer than two tones, decodes as none.
  - There is no `Quality` `DiskCode` table.
- **Block codes 27–32 and the `DiskCode` tables are pinned when their `BlockRef`s are born** (Task 7), not in the codec task. They are frozen either way.
  - BPM is `BlockRef::Tempo`, with `disk_code() -> None`, and is saved through the `Tempo` record.
  - DEGREE is a cell (`OrbitCell::Degree`), saved in `OrbitChord`.
  - So the ORBIT block (27) holds exactly KEY, SCALE, BARS and SEGS, as § 8 says.
- **ORBIT's records sit at the top level, after the six Parts.** An ORBIT tag closes the open Part context (`SoundCheck::finish`) and is routed by tag. Before the six Parts it is `Corrupt`. It is also `Corrupt` in a Sound file and in SYSTEM.

**The engine**
- **`NoteOrigin { Live, Orbit(RingIdx) }`**, not `Origin`. That name is projects-core's `project::Origin`. The ring is in it so rings don't release each other (Review Focus 4).
- **Offs at least one block late.** An off is due at `max(step + gate·step_len, step + 96)` samples. Since a step is at `t − 32` or later, that is `t + 64` or later: always a later window than its on (Review Focus 1).
- **Contiguous windows** (controller ruling). The runner keeps `edge: Position`, the previous block's `to`. Each `Span` is `from = edge`, `to = clock.position(t + 32)`. Start sets `edge = Position::ZERO`. A BPM change calls `set_bpm(at, edge, bpm)`, which re-anchors `edge` at its sample `max(t − 32, anchor)`. `position` of a sample before the anchor saturates to the anchor's position.
- **Events are sized for the worst case** (controller ruling). A window never holds two step boundaries of one ring: that is the advance cap, and a const assert ties `MAX_BPM_EXT` to `MAX_STEPS`. So `EVENTS_PER_RING` = 2 is the worst case. Task 12's `max_tempo_32_steps_fits_events` pins it under the fastest MIDI clock, jumps included.
- **The transport acts on edges** (controller ruling).
  - A false → true edge of `OrbitShared.run` starts, and a true → false edge stops.
  - A project load (a new epoch) or a MIDI Stop stops the runner without an edge. Only a fresh false → true edge starts it again.
  - The UI's B6 sets `run = !view.running`. When the view reports stopped while `run` is true, the UI clears `run` once.
  - The sound is `transport && ext_playing`. `ext_playing` is true under the internal clock, set by MIDI Start or Continue, cleared by Stop, and it survives the fallback to the internal clock.
- **`block` takes the working scene `&mut`**, because MUTATE drifts it (§ 4.1). It borrows the queued scene (`cue: Option<&Scene>`, from `shared.orbit.settings`) and copies it in at the boundary. The runner stores no second scene. While a cue is pending, the runner copies no knobs. The spec's `ClockOut` folds into `Span`.
- **MIDI Start holds the phase at 0 until the first Clock**, which is the downbeat. The n-th Clock after Start marks `(n − 1)/96`. Under a leading MIDI clock, a B6 start resets the walks and the `Rng`s but never the position, so it joins in phase (§ 6.3).

**The drift and the scenes**
- **The drift lives in the `Project`** (controller ruling).
  - `OrbitSong::absorb(&OrbitView)` runs on each loop boundary the view reports (`OrbitView.loops`), while no switch is queued. It copies each ring's mask, notes and pool into `live` without bumping the revs.
  - So STOP then PLAY keeps the drift, SAVE is a copy of `live`, and a project save includes the drift.
  - The consequence: MUTATE marks the project Modified. A NEW project that has only been listened to will prompt on `+ CREATE NEW` or on a load. That is a UAT question (item 9).
- **Where the scenes live.** They live in the `Project`, as `Project::orbit()`, from Task 7: ORBIT's settings are project data. `Project`'s `&mut` accessors bump its `rev`, so `project_status` (cached on `rev`, ADR 0066) sees ORBIT edits and absorbs. NEW's `OrbitSong`:
  - `live = Scene::init()`, `scenes[0] = Scene::init()`, `scenes[1..8] = Scene::neutral()`, `current = 0`, 120 BPM;
  - written in place by `init_in_place` and `reset_new`.

  A decode's base is all-neutral at 120 BPM. The transport (`run`) is UI state, never saved.
- **A scene SAVE while a switch is queued is refused** with the toast `SWITCH PENDING`, since `live` would be the queued scene's.
- **A project save while a switch is queued saves the landing:** `live` (the queued scene) and `current` = the queued index, as if it had landed (Review Focus 7).

**The navigation** (amended 2026-10-02 for nav-core)
- **ORBIT is a `Location`.** `Loc::Orbit(OrbitAt)`; `OrbitAt { page: PageAt, ring: RingIdx }`, its page always one of `ORBIT_CHAIN`'s. `Location::page` returns `(&ORBIT_CHAIN, at.page)`, so the page renderer draws it like any chain page. `Location::part` is `None` there, so `UiState::go` leaves `active_part` alone in ORBIT.
- **`Recall` gains `orbit: OrbitAt`** (the ORBIT page last left, `OrbitAt::HOME` at first) **and `orbit_from: Outside`** (where SEQ hold came from). `Outside::new` now refuses `Orbit` as well as `Settings`. So `settings_from` and `orbit_from` are both sound-side places, by type.
- **SEQ hold** is `NavKey::SeqHold`, from the SEQ gate's `Press::Hold`:
  - from a sound-side place: `orbit_from = Outside::new(here)`, then `Orbit(recall.orbit)`;
  - from inside SETTINGS: SETTINGS closes as MENU at its top would, `orbit_from = recall.settings_from`, then `Orbit(recall.orbit)`;
  - with a prompt or NAMING open: nothing (a modal takes every key but B*n*);
  - inside ORBIT it can't be expressed: `OrbitKey` has no SEQ hold.
- **Keys in ORBIT are an `OrbitKey`,** built by `UiState::orbit_keys` instead of `nav_keys` when `loc.orbit()` is `Some`, and stepped by `OrbitAt::step`:
  - `Ring(RingIdx)`: a B1–B5 tap, on release; selects the ring and opens RING on its last sub-page;
  - `Cross(RingIdx)`: a B1–B5 hold; to `Pages(p, recall.pages_of(p, cx))`, `p` the ring's target Part from `NavCtx.orbit`;
  - `Mute(RingIdx)`: MIX + B1–B5, on the press; the B gate is muted for that press, so no tap or hold follows;
  - `PlayStop`: B6, on the press;
  - `Plus`, `Minus`: along ORB · RING · CHRD · SCN, clamped;
  - `Edit`: cycles RING's sub-pages, and CHRD ↔ CUSTOM while SCALE is CUSTOM (`NavCtx.orbit.custom`); nothing elsewhere;
  - `SeqTap`: `Step::Orbit(OrbitAct::SaveScene)`, on every ORBIT page, never a page move;
  - `MenuTap`: leaves to `orbit_from` (owner, Q1); a second tap, now outside ORBIT, opens SETTINGS.

  MIX + B6, EDIT + B*n* and encoder A as a list bar don't exist in ORBIT. MENU hold is nav-core's quick save, before any key, everywhere (ADR 0066).
- **`Step` gains `Orbit(OrbitAct)`,** `OrbitAct { PlayStop, Mute(RingIdx), SaveScene }`, which `UiState` runs, as it runs `Step::Act`. `step` stays pure.
- **`NavCtx` gains `orbit: OrbitCx { targets: [PartId; RINGS], custom: bool }`,** filled by `nav_cx` from the project (ring *n* → Part *n* until Task 7 puts `OrbitSong` in the project).
- **`HoldGates` gains `rings: [HoldGate; RINGS]`** (pre-flight: B1–B5 only; B6 has no hold, so it gets no gate), each muted while MIX is down, as MENU is (nav-core's `muted` input), and `Presses` gains `ring: [Option<Press>; RINGS]`, indexed by `RingIdx`. Outside ORBIT, B*n* keeps acting on the press; its gate runs every frame anyway, so it is in step on entry.
- **SETTINGS › ORBIT** replaces `Later(issue(262))` with a list that acts on the playing scene, as SETTINGS › PART acts on the active Part (Task 17).
- **ADR 0044 is amended in place** (Proposed) with `Loc::Orbit`, `OrbitKey` and the MENU rule (owner, Q1), marked "(amended 2026-10-02, owner: …)". ORBIT's own nav ADR (the old plan's 0061) is not written: 0044 already holds ORBIT's keys. It also corrects its citation: ADR 0044's MENU-hold row cites "orbit spec lines 370 and 570: 'MENU hold: save the project'", but those lines (at `ee4380f`) read "Leave, to System, as today" and "MENU leaves as today". Quick save in ORBIT stands on ADR 0066 (owner, Q2), not on the ORBIT spec.

**The UI**
- **SCALE offers all ten named scales and CUSTOM.** § 7.1's "MAJOR, MINOR and CUSTOM" conflicts with § 8's `ScaleKind` codes 0–10 and with § Design choices. The latter two win.
- **Slice 1's RING has one sub-page,** RHYTHM. EDIT's cycle is written over the sub-page count, and three EDITs return to RHYTHM once VOICE and NOTES land (Task 13).
- **SEQ tap in ORBIT is a no-op until scenes exist** (Task 16). It never moves a sub-page in ORBIT.
- **CHRD › CUSTOM** (controller ruling). EDIT keeps cycling sub-pages, per ADR 0044: on CHRD, while SCALE is CUSTOM, it cycles CHRD ↔ CUSTOM. On CUSTOM:
  - encoder A moves the cursor round the 12 notes;
  - encoder B turned right sets the note on, and turned left sets it off;
  - the root stays locked on.

  Spec § 7.1, § 7.2, § Design choices and the `chrd_custom_circle` row are amended to match.
- **NOTES' sixth cell** (§ Design choices leaves it to this plan) is NOTE: the selected chip's note, in semitones. MIX + NOTE's encoder picks the chip, as MIX + DEGREE picks a segment. CLEAR turned up clears; turned down, it fills the pool or steps with random notes of the key in the register (MUTATE's swap rule, § 2.2 choice 7).
- **ORBIT is reachable only when built with it** (pre-flight: `chimera-core`'s `orbit` feature, Global Constraints, replaces `UiState::set_orbit_enabled`; SETTINGS' tree is a static table, so a runtime flag couldn't pick its row). The desktop always has it; the firmware only under `orbit`. Without it, SEQ hold does nothing, and SETTINGS › ORBIT stays `Later(issue(262))`.
- **The header in ORBIT** is `Head::Orbit(SceneIdx)`: `SCENE n ORBIT` over `KEY SCALE · n BAR · BPM SOURCE`.

**The milestone**
- **The fresh project's Parts are projects-core's NEW: INIT Algo ×6.** The init scene is tuned against them.
  - Task 11's `ORBIT_QA_WAV` render writes an A/B pair for comparison: the NEW project, and the same scene with factory Sounds on Parts 1–5.
  - If the owner prefers B, the remedy is the NEW template. That is an owner decision (UAT item 1), and never ORBIT writing Parts.
- **Projects saved before ORBIT existed load with neutral scenes, every ring muted,** and the desktop boots the last project. So every "fresh project" check starts from SETTINGS › PROJECT › LOAD PROJECT › `+ CREATE NEW`, or from an empty `CHIMERA_CARD`.

### Task 2: The clock's maths
**Files:**
- Create: `chimera-core/tests/orbit_clock_test.rs`
- Modify: `chimera-core/src/orbit/clock.rs`

**Interfaces:**
- Produces:

```rust
pub struct Phase(u32);                  // fraction of a bar, 2⁻³²: new, get, ZERO
pub struct Position { pub bar: u32, pub phase: Phase }   // Ord; ZERO
pub struct Bpm(u16);                    // 30..=300: new -> Option, clamped, get, DEFAULT (120)
pub const WINDOW: u64 = 32;             // half a block (§ 6.2)
pub const MAX_BPM_EXT: u32 = 1200;      // the advance cap (Global Constraints)
pub const fn step_start(k: u8, steps: Steps) -> Phase;   // ⌈k · 2³² / n⌉
pub const fn step_at(phase: Phase, steps: Steps) -> u8;  // ⌊phase · n / 2³²⌋, a u64 multiply
pub struct InternalClock { /* anchor sample, anchor Position, bpm, sample_rate */ }
impl InternalClock {
    pub const fn start(at_sample: u64, bpm: Bpm, sample_rate: u32) -> Self;  // Position::ZERO at `at_sample`
    pub fn anchor(&self) -> u64;
    pub fn position(&self, sample: u64) -> Position;     // before the anchor: the anchor's position
    pub fn sample_of(&self, pos: Position) -> u64;       // the inverse, rounded to nearest
    pub fn bar_len(&self) -> u32;                        // samples per bar, rounded
    pub fn set_bpm(&mut self, at: u64, pos: Position, bpm: Bpm);  // re-anchor: `pos` at sample `at`
    pub fn bpm(&self) -> Bpm;
}
```

The maths is exact rational: samples per bar = `sample_rate · 240 / bpm`. Compute in whole bars plus a remainder in `u64`, so no `u128` is needed.

- [ ] **Step 1: Write the failing tests** in `orbit_clock_test.rs`:
  - `step_index_is_exact_for_any_count`: for every n in 1..=32 and k in 0..n, `step_at(step_start(k)) == k`, and `step_at(Phase(step_start(k).get() - 1)) == k - 1` for k > 0. A bar holds exactly n steps.
  - `internal_clock_never_drifts`: 97 BPM at 48 kHz for one hour. For every bar n, `sample_of(Position { bar: n, phase: ZERO }) == round(n · 48000 · 240 / 97)`, and `position` at that sample is bar n, phase 0. (`Bpm` is integral per § Design choices, so the spec's 97.3 becomes 97.)
  - `bpm_change_keeps_the_position` (Review Focus 2): at 120 BPM, `p = position(99_968)`, then `set_bpm(99_968, p, 60)`. `position(99_968) == p`, and the position then advances at half the rate.

**`block`, in this order:**
1. **Offs.** Each ring's pending off that falls due before `span.to_sample` goes out.
2. **The loop boundary, once.** If the window holds one (`bar % BARS == 0`, phase 0):
   - if `cue` is `Some`, it is copied into `scene`, the walks and `Rng`s reset from its seed, `fresh` is set, and `adopted` is reported. Pending offs are kept;
   - otherwise, unless `fresh`, each ring with MUTATE > 0 gets `mutate` against the new loop's segment-0 harmony, and `apply`;
   - `fresh` clears after the boundary.
3. **Steps, per ring.** A step boundary `step_start(k)` of the ring's current STEPS in `[from, to)` is played with `Ring::play(k, …)`. It uses the harmony of `segment_at` of the step's own position, so two rings either side of a segment boundary in one window each get their own chord. If that ring's earlier pending off is still held, it goes out first.
4. **Timing.** The step's sample is `from_sample + (step − from)·(to_sample − from_sample)/(to − from)`, in phase units. That works under both clocks. A `NoteOut` becomes an On on `channels[target]`. Its off is due at `max(step_sample + gate · step_len, step_sample + 96)`, with the channel stored, where `step_len = bar_len / STEPS`.

```rust
// ui/led.rs — pure: the shell only copies `on()` to the pin
pub const BEATS_PER_BAR: u32 = 4;              // a bar is four beats (Global Constraints)
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum Pulse { Beat, Downbeat }
impl Pulse { pub const fn of(beat: u32) -> Pulse; }   // beat % 4 == 0: Downbeat
pub const BEAT_TICKS: u8 = 1;                  // 50 ms at UI_FPS = 20
pub const DOWNBEAT_TICKS: u8 = 3;              // 150 ms, the header dot's fade
#[derive(Clone, Copy, Debug, Default, PartialEq, Eq)]
pub struct Led(u8);                            // UiTicks left lit
impl Led {
    pub const OFF: Led;
    pub const fn step(self, p: Option<Pulse>) -> Led;  // a pulse lights for max(left, its length); else one tick less
    pub const fn on(self) -> bool;
}
```

**Rules:**
- `OrbitView.beats` counts beats from Start, `pos.bar · 4 + ⌊phase / 2³⁰⌋`, under either clock. A change of `beats` in a `UiTick` is one pulse, `Pulse::of` the newest beat, however many beats a stalled frame skipped.
- Stopped, the LED is off at the next `UiTick` and stays off.
- **The pin** (checked against main and `usb-console`): PB1 is unused. It is TIM1_CH3N (AF1), TIM3_CH4 (AF2) or TIM8_CH3N (AF3). TIM1 is the backlight's (CH2 on PE11, 20 kHz, `ComplementaryDisabled`), so PB1 never goes on TIM1. TIM3 and TIM8 are free, but a hard pulse needs no timer: PB1 is a push-pull GPIO, driven low from boot in every build so it never floats, and set from `ui.led()` after each `update` under `orbit`. A fade or breath later goes on TIM3_CH4 (#307). Other GPIOB pins in use: PB7 (MIDI RX), PB14 and PB15 (SPI2); USB is PA11/PA12.
- The desktop shows no LED: it is checked on the unit (Task 21, UAT 12).
