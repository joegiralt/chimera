# ORBIT Implementation Plan

**Goal:** ORBIT plays on the desktop: five Euclidean rings over a chord ring, snapped, mutating, with its pages, transport and ADR 0044 navigation (Slice 1, "sounds good 10 seconds after PLAY"), then VOICE, NOTES, STEP rings, scenes, capture, live snapping, MIDI clock and saving in the project file (Slice 2). The firmware builds it behind the `orbit` feature, off by default.

**Architecture:**
- **Functional core:** `chimera-theory` (merged) and `chimera-core::orbit`. The rings, walks, MUTATE and dice are built (`orbit-core`, 27 tests). This plan adds the chord ring, the clock's maths, the scene and `block()`: pure functions of state, settings and a span of samples.
- **Audio shell:** `orbit::runner::OrbitRunner`, in core, owned by each shell's audio callback. Per 64-sample block it reads `AudioShared.orbit`, steps the clock, calls `block`, and hands each event to `Instrument::handle` with a `NoteOrigin`.
- **UI:** `ChainId::Orbit` with the ORB, RING, CHRD and SCN pages in `chimera-core::ui::orbit`. A pure `ui::hold::HoldGate` gives tap and hold. The scene lives in the `Project`. The engine reports back through an `OrbitView` triple buffer.

**Tech Stack:** Rust 2024, `no_std` core, `chimera-theory`, no new dependency. `just check`, `just test`, `just desktop`, `just firmware`.

**Spec:** `docs/superpowers/specs/2026-09-30-orbit-design.md` (owner-approved). Navigation: ADR 0044 (Proposed, branch `nav-ladder-adr`, `docs/adr/0044-one-ladder-one-button-map.md`). The built core: `chimera-core/src/orbit/`, `chimera-core/tests/orbit_core_test.rs`.

## Global Constraints

- **Pure core** (spec § Principles). `chimera-theory` and `chimera-core::orbit` take no time source but their arguments. The shells are thin.
- **Types decide what's possible** (ADR 0012). `RingIdx`, `Steps`, `Fill`, `Pool`, `Pct`, `Octave`, `Bars`, `Segs`, `Bpm`, `SceneIdx` and the rest are checked newtypes or enums. Build nothing out of range.
- **The audio thread never allocates or blocks.** At most two events per ring per block (one off, one on), in a fixed array.
- **Parts can't tell ORBIT from a keyboard.** ORBIT's notes enter `Instrument::handle` and take voices by the allocator's rules, with no priority and no reserved voices (§ 9).
- **Deterministic.** Every draw comes from a ring's own seeded `Rng` (§ 2.2, choice 10). The same scene from the same Start gives the same events, sample for sample.
- **Never snap the UI** (CLAUDE.md). The ORB sweep and dot flashes animate from the reported position.
- **Timing** (§ 6.2):
  - a bar is four beats, 96 MIDI clocks;
  - the position is `(bar: u32, phase: u32)`, with phase in units of 2⁻³² of a bar;
  - a block fires the steps in `[t − 32, t + 32)` around its start sample `t`.
- **Hold:** `ui::hold::HOLD_MS` = 500, shared by MENU, SEQ and B*n* (ADR 0044). A tap acts on release; a hold fires once at `HOLD_MS`, and its release does nothing.
- **Ranges** (§ Design choices): STEPS 1–32, SEGS 1–8, BARS 1–8, OCTAVE 0–8 (C4 = 60), BPM 30–300 in steps of 1 (default 120), ACCENT_BOOST +30 capped at 127, `RESNAP_GLIDE_MS` = 40.
- **Memory:** `size_of::<OrbitRunner>() <= 1024`, asserted at compile time. Every new AXI static is counted in `AXI_RESIDENT`.
- **Storage** (ADR 0045): codes are frozen and append-only, and every enum has an exhaustive `DiskCode` table pinned in `tests/fixtures/disk_codes_v1.txt`. ORBIT's records are non-critical, and each is under `MAX_RECORD_LEN` = 512.
- **Firmware:** the `orbit` cargo feature of `chimera-stm32`, off by default. `just firmware` builds with and without it. Flashed once, at ship, when the owner says it feels right.
- **Repo rules:**
  - every `unsafe` has a `// SAFETY:` comment; no libc, no heap on the audio path;
  - decisions that constrain later work get an ADR in `docs/adr/`, listed in its README; never edit an accepted ADR;
  - bugs and follow-ups go in GitHub issues (joegiralt/chimera), referenced by URL.
- **Commits:**
  - a terse plain sentence, with no type prefix;
  - stage files by name. Run `git status` first. **Never stage `docs/chimera-ui-ux-spec.md` or `chimera.bin`.**
- `just check` passes before every commit. No task ends red.
- **QA before UAT:** Claude runs each slice's desktop QA gate (tests, the parameter sweep, the scripted ORBIT render). The owner only judges by ear, from the UAT list.

## Review Focus

These are the inputs the spec implies but no spec test exercises, most likely to bite first. Each one's test is in the task named.

1. **A gate shorter than a block**, such as GATE 0 %, or 1 % at 300 BPM on 32 steps. The off would be scheduled inside the block that sends its on. Offs go out before ons, so the voice would stick. Every off lands at least one block after its on. Task 3: `gate_zero_never_sticks`.
2. **BPM turned while playing.** A clock that recomputed the phase from the sample count at the new BPM would jump, re-fire or skip steps. The position carries on from where it was. Task 2: `bpm_change_keeps_the_position`; Task 3: `bpm_sweep_fires_every_step_once`.
3. **A Part's CHANNEL or a ring's TARGET changed while a note is held.** The off must go to the channel the on went to, or the voice sticks. Task 3: `pending_off_keeps_its_channel`.
4. **Two rings on one Part playing the same note.** One ring's gate must not release the other's voice, even under Mono. So `NoteOrigin::Orbit` carries the ring. Task 4: `two_rings_on_one_note_release_their_own`.
5. **STEPS cut, or a ring muted, while its note is held.** For example, STEPS 13 → 5 at step 12. The pending off still fires on time. Task 3: `edits_mid_gate_never_strand_a_note`.

## Decisions this plan makes where the spec is silent or ambiguous

- **Record tags.** The spec's 0x0007–0x000C collide with projects-core, which takes 0x8007–0x000A (by the low 15 bits) and keeps 0x0B–0x0F for its reserved records. The ORBIT records take:
  - `Tempo` = 0x000B, the tempo slot the projects spec reserves;
  - `OrbitBlock` 0x0010, `OrbitNotes` 0x0011, `OrbitChord` 0x0012, `Orbit` 0x0013, `OrbitScale` 0x0014.

  The payloads are § 8's.
- **`NoteOrigin { Live, Orbit(RingIdx) }`**, not `Origin`. That name is projects-core's `project::Origin`. The ring is in it so rings don't release each other (Review Focus 4).
- **Block codes 27–32 and the `DiskCode` tables are pinned when their `BlockRef`s are born** (Task 7), not in the codec task. They are frozen either way. BPM is `BlockRef::Tempo`, with no block code, saved through the `Tempo` record, as `Channels` is saved elsewhere. DEGREE is a cell (`OrbitCell::Degree`), saved in `OrbitChord`. So the ORBIT block (27) holds exactly KEY, SCALE, BARS and SEGS, as § 8 says.
- **SCALE offers all ten named scales and CUSTOM.** The § 7.1 line "MAJOR, MINOR and CUSTOM" conflicts with § 8's `ScaleKind` codes 0–10 and with § Design choices. The latter two win.
- **Offs at least one block late.** An off is due at `max(step + gate·step_len, step + 96)` samples. That puts it in a later block's window than its on (Review Focus 1).
- **BPM re-anchors.** `InternalClock::set_bpm(now, bpm)` restarts the sample count from `position(now)`. "Computed, not accumulated" holds between tempo changes.
- **`block` takes the working scene `&mut`,** because MUTATE drifts it (§ 4.1). It also takes the queued scene, which it adopts at the boundary. The spec's `ClockOut` folds into `Span`.
- **Where the scenes live.** They live in the `Project`, as `Project::orbit()`, from Task 7: ORBIT's settings are project data. `project_crc` covers them once Task 17 adds their records. The transport (`run`) is UI state, never saved.
- **Slice 1's RING has one sub-page,** RHYTHM. EDIT's cycle is written over the sub-page count, and three EDITs return to RHYTHM once VOICE and NOTES land (Task 13).
- **SEQ tap in ORBIT is a no-op until scenes exist** (Task 16). It never moves a sub-page in ORBIT.
- **Button timing:**
  - Outside ORBIT, MENU keeps acting on `Pressed` (System) until the navigation plan's ladder.
  - In ORBIT, MENU goes through the gate.
  - B1–B5 in ORBIT act on the tap's release, so a hold never also picks a ring.
  - B6 and MIX + B*n* act on `Pressed`: they have no hold meaning, and the transport wants no latency.
- **Hold B*n* lands on Part *p*'s pages where they were left** when Modal 2's `sound_left` is that Part's, else on its home page. The navigation plan's `Recall.pages[6]` generalises it.
- **CHRD › CUSTOM:** EDIT toggles the note, as § 7.1, § 7.2 and `chrd_custom_circle` say. You leave CUSTOM with MINUS or PLUS, and CHRD reopens on its main page. This is on the UAT list.
- **NOTES' sixth cell** (§ Design choices leaves it to this plan) is NOTE: the selected chip's note, in semitones. MIX + NOTE's encoder picks the chip, as MIX + DEGREE picks a segment. CLEAR turned up clears; turned down, it fills the pool or steps with random notes of the key in the register (MUTATE's swap rule, § 2.2 choice 7).
- **ORBIT is reachable only when the shell enables it** (`UiState::set_orbit_enabled`). The desktop always enables it; the firmware does only under `orbit`. Without it, SEQ hold does nothing.
- **The fresh project's Parts are projects-core's NEW: INIT Algo ×6.** The init scene is tuned against them. If the owner hears INIT as too plain at UAT, the remedy is the NEW template (say, Parts 1–5 taking factory Sounds). That is an owner decision, asked in UAT item 1, and never ORBIT writing Parts.

### Task 2: The clock's maths

**Files:**
- Create: `chimera-core/tests/orbit_clock_test.rs`
- Modify: `chimera-core/src/orbit/clock.rs`

**Interfaces:**
- Produces:

```rust
pub struct Phase(u32);                  // fraction of a bar, 2⁻³²: new, get, ZERO
pub struct Position { pub bar: u32, pub phase: Phase }   // Ord
pub struct Bpm(u16);                    // 30..=300: new -> Option, clamped, get, DEFAULT (120)
pub const WINDOW: u64 = 32;             // half a block (§ 6.2)
pub const fn step_start(k: u8, steps: Steps) -> Phase;   // ⌈k · 2³² / n⌉
pub const fn step_at(phase: Phase, steps: Steps) -> u8;  // ⌊phase · n / 2³²⌋, a u64 multiply
pub struct InternalClock { /* anchor sample, anchor Position, bpm, sample_rate */ }
impl InternalClock {
    pub const fn start(at_sample: u64, bpm: Bpm, sample_rate: u32) -> Self;  // bar 0, phase 0 at `at_sample`
    pub fn position(&self, sample: u64) -> Position;     // from the anchor, never accumulated
    pub fn sample_of(&self, pos: Position) -> u64;       // the inverse, rounded to nearest
    pub fn bar_len(&self) -> u32;                        // samples per bar, rounded
    pub fn set_bpm(&mut self, now: u64, bpm: Bpm);       // re-anchors at position(now)
    pub fn bpm(&self) -> Bpm;
}
```

The maths is exact rational: samples per bar = `sample_rate · 240 / bpm`. Use a `u128` intermediate if a `u64` would overflow over hours. Task 18's bench row measures its cost.

- [ ] **Step 1: Write the failing tests** in `orbit_clock_test.rs`:

For every bar n, `sample_of(Position { bar: n, phase: ZERO }) == round(n · 48000 · 240 / 97)`, and `position` at that sample is bar n, phase 0. (Deviation: `Bpm` is integral, per § Design choices.)

### Task 3: The scene and `block`

**Files:**
- Create: `chimera-core/src/orbit/scene.rs`, `chimera-core/src/orbit/engine.rs`, `chimera-core/tests/orbit_engine_test.rs`
- Modify: `chimera-core/src/orbit/mod.rs`

**Interfaces:**
- Consumes: Tasks 1–2; `Ring::{play, apply}`, `mutate`, `Rng::for_ring`, `WalkState::START` (built); `PartId` (projects-core); `MidiChannel` (hal).
- Produces:

```rust
// scene.rs
pub const SCENES: usize = 8;
pub struct SceneIdx(u8);                  // 0..8: new, get, ALL
pub enum Target { Part(PartId) }          // Kit(..) is Slice 3
pub struct SceneRing { pub ring: Ring, pub target: Target, pub rhythm_rev: u8, pub notes_rev: u8 }
pub struct Scene { pub chords: ChordRing, pub rings: [SceneRing; RINGS], pub seed: u32 }
impl Scene { pub fn init() -> Scene; pub fn neutral() -> Scene; }  // neutral: every ring muted, chord ring NEUTRAL (§ 8)
// engine.rs
pub struct PendingOff { pub channel: MidiChannel, pub note: Note, pub at: u64 }
pub struct OrbitState { /* walks, rngs, pending: [Option<PendingOff>; RINGS], fresh: bool, seg: u8 */ }
impl OrbitState {
    pub fn start(scene: &Scene) -> OrbitState;   // walks START, rngs from (seed, ring), fresh
    pub fn stop(&mut self) -> Events;            // every pending off, now, and nothing else
    pub fn forget(&mut self);                    // drop pending offs (their voices were killed)
    pub fn harmony(&self, scene: &Scene) -> Harmony;
    pub fn seg(&self) -> u8;
}
pub struct Span { pub t: u64, pub from: Position, pub to: Position, pub bar_len: u32 }  // window [t−32, t+32)
pub enum OrbitKind { On(Velocity), Off }
pub struct OrbitEvent { pub ring: RingIdx, pub channel: MidiChannel, pub note: Note, pub kind: OrbitKind }
pub struct Events { /* offs and ons: [Option<OrbitEvent>; RINGS] each */ }
impl Events { pub fn iter(&self) -> impl Iterator<Item = OrbitEvent> + '_; pub fn len(&self) -> usize; }  // offs first, ring order
pub fn block(st: &mut OrbitState, scene: &mut Scene, cue: &mut Option<Scene>, span: Span,
             channels: &[MidiChannel; MAX_PARTS]) -> Events;
```

**`block`, per ring, in ring order:**
1. A pending off due in the window goes out.
2. At a loop boundary (`bar % BARS == 0`, phase 0) in the window, in this order:
   - if `cue` holds a scene, it replaces `scene`, and the walks and `Rng`s reset from its seed, with `fresh` set;
   - otherwise, unless `fresh`, each ring with MUTATE > 0 gets `mutate` against the new loop's segment-0 harmony, and `apply`;
   - `fresh` clears after the boundary.
3. Each step boundary `step_start(k)` of the ring's current STEPS that falls in the window is played with `Ring::play(k, …)`. If an earlier pending off is still held, it goes out first.
4. A `NoteOut` becomes an On on `channels[target]`. Its off is due at `max(step_sample + gate · step_len, step_sample + 96)`, with the channel stored.

- ring *n* targets Part *n*;
- the rings:
