# USB MIDI Implementation Plan

**Goal:** The unit is a composite USB device (CDC console plus a one-cable USB MIDI 1.0 function), serviced from the `OTG_FS` interrupt, with a storm guard so the console and `update` always survive.

**Architecture:** `UsbDevice`, `SerialPort` and the MIDI class live in one static cell. The `OTG_FS` handler polls it; the UI reaches it through `with`, which masks `OTG_FS`. Bank 1 keeps the shim, the cell, `with`, the guard and a closed path (console poll plus a MIDI drain). Bank 2 (`BoardDoor`) polls console and MIDI, feeds USB's own `PipeSlot`, and packs USB's out ring. The packet codec is pure, in `chimera-midi`.

**Tech Stack:** Rust no_std, usb-device 0.3.2, usbd-serial 0.2.2, synopsys-usb-otg 0.4.0 (not vendored), `usbd-midi` (MIT) or an in-tree class, stm32h7xx-hal.

**Spec:** `docs/superpowers/specs/2026-11-02-usb-midi-design.md`. **§ 13's rulings override §§ 4–10** where they differ.

## Global Constraints

- Bank 1 frozen (ADR 0198): only the shim, cell, `with`, guard, closed path, statics and `stats` lines grow it; `just check-bank1` passes with lines raised under ADR 0222. Over 2 KB on a set: move more behind the door first.
- `door-check` passes: no bank-1 reference into bank 2, no bank-2 vtable in bank-1 rodata.
- VID:PID 0483:5740 kept; `bcdDevice` bumped; product string "Chimera"; jack names "Chimera".
- `OTG_FS` at `Priority::MIDI`. Audio untouched. No SOF interrupt.
- Feature `midi-usb` (chimera-board and chimera-stm32), on wherever `midi-din` is, including bench sets. Without it the console is byte-for-byte today's polled one.
- No `unsafe` without `// SAFETY:`. No heap. Commits terse, no type prefixes, never stage `chimera.bin`.
- Builds: `nice -n 15`, `CARGO_BUILD_JOBS=10`, at most two heavy builds at once. Targeted tests per task; full `just check` in Task 7.
- Hardware: run `status` alone and see SAVED before any flash; flash only at 0x08020000 via `chimera-usb.py update <bin> <bk2>`, never wrapped in a timeout; never DFU alt 1, never 0x08000000.

## Review Focus

1. A console `put` while a USB note stream plays: the shared RX FIFO must never hold a MIDI packet unread (Task 4's under-`with` path; tested on the unit in Task 8).
2. A gate build's `bank2 erase` while a host has MIDI open: the console still answers, no fault (Task 4's closed drain; Task 8).
3. A host that writes console bytes faster than the UI reads them (8 KB, no newline): the guard trips and the console recovers (Task 3).
4. A full or unread USB out ring (no host, or host not reading): DIN's echo is never held back (Task 6 test).
5. A host that sleeps mid-chord: suspend releases the notes (Task 5 test on the pipe entry; unit in Task 8).
