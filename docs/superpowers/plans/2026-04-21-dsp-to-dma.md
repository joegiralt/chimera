# DSP Engine to DMA Buffer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the hardcoded 440 Hz sine in the DMA ISR with real Voice rendering — FM/Modal engine through the full signal chain (Drive → Filter → Wavefolder → VCA), producing actual synthesizer audio from a single voice triggered by a fixed note.

**Architecture:** Change BLOCK_SIZE from 128 to 64 to match the DMA half-buffer (64 stereo pairs). The DMA ISR calls a `render_audio()` function that renders one Voice into an f32 work buffer, converts to i16 stereo, and writes to the DMA half-buffer. A static Voice and ParamSnapshot live in RAM_D2 alongside the DMA buffer. The voice is triggered once at startup with a fixed note (A4/440Hz).

**Tech Stack:** Rust no_std, `chimera-core` DSP (Voice, FmEngine), `chimera-stm32` (DMA ISR)

**Spec:** `docs/superpowers/specs/2026-04-20-dma-audio-design.md`, `docs/chimera-product-architecture.md` (Section 4: Chain Architecture)

---

## Scope

This plan wires ONE voice to ONE DAC. No polyphony, no MIDI, no voice allocation, no mixer. Just: Voice renders into DMA buffer. The simplest thing that proves the DSP-to-DMA pipeline works.

After this plan:
- Turning encoders on the FM page changes the sound in real time
- The full signal chain (FM → Drive → Filter → Wavefolder → VCA) is audible
- The DMA runs glitch-free during UI interaction

```rust
use chimera_core::dsp::voice::Voice;
use chimera_core::params::ParamSnapshot;
use chimera_hal::BLOCK_SIZE;

/// DMA audio buffer in RAM_D2 — 256 × i16 = 128 stereo pairs (64 per half).
/// Sized for BLOCK_SIZE=64: each half = 64 stereo pairs = 128 i16.
#[unsafe(link_section = ".ram_d2")]
static mut AUDIO_BUF: [i16; 256] = [0; 256];

/// f32 work buffer for Voice rendering — one BLOCK_SIZE mono block.
static mut WORK_BUF: [f32; BLOCK_SIZE] = [0.0; BLOCK_SIZE];

/// Single voice instance for audio rendering.
/// Only accessed from DMA ISR (single, non-reentrant).
static mut VOICE: Option<Voice> = None;

/// Parameter snapshot pointer — written by UI thread, read by audio ISR.
/// The UI thread updates this atomically (pointer swap).
/// For now, we use a simple static that both threads access.
/// This is safe because ParamSnapshot is read-only in the ISR.
static mut PARAMS: Option<*const ParamSnapshot> = None;
```

- [ ] **Step 3: Add render_block function**

```rust
/// Render one block of audio from the Voice into the DMA half-buffer.
/// `offset` is 0 for first half, 128 for second half.
fn render_block(offset: usize) {
    // SAFETY: only called from single non-reentrant ISR
    unsafe {
        let voice = match VOICE.as_mut() {
            Some(v) => v,
            None => {
                // No voice initialized — fill with silence
                for i in 0..128 {
                    AUDIO_BUF[offset + i] = 0;
                }
                return;
            }
        };

        let params = match PARAMS {
            Some(p) => &*p,
            None => {
                for i in 0..128 {
                    AUDIO_BUF[offset + i] = 0;
                }
                return;
            }
        };

        // Render BLOCK_SIZE (64) mono f32 samples
        voice.render(&mut WORK_BUF, params, chimera_hal::SAMPLE_RATE);

        // Convert f32 mono → i16 stereo, write to DMA half-buffer
        // 64 mono samples → 64 stereo pairs → 128 i16 values
        for i in 0..BLOCK_SIZE {
            // Clamp and convert f32 (-1.0..1.0) to i16
            let clamped = WORK_BUF[i].clamp(-1.0, 1.0);
            let sample = (clamped * 32767.0) as i16;
            AUDIO_BUF[offset + i * 2] = sample;     // left
            AUDIO_BUF[offset + i * 2 + 1] = sample; // right (mono for now)
        }
    }
}
```

```rust
#[interrupt]
fn DMA1_STR0() {
    // SAFETY: ISR has exclusive access to DMA1 status/clear registers
    let dma1 = unsafe { &*pac::DMA1::ptr() };

    if dma1.lisr.read().htif0().is_half() {
        dma1.lifcr.write(|w| w.chtif0().clear());
        render_block(0);
    }

    if dma1.lisr.read().tcif0().is_complete() {
        dma1.lifcr.write(|w| w.ctcif0().clear());
        render_block(128);
    }
}
```

- [ ] **Step 6: Add init_voice function**

```rust
/// Initialize the voice and connect it to parameter snapshot.
/// Call after UI is set up, before DMA starts.
///
/// # Safety
/// `params_ptr` must point to a ParamSnapshot that outlives the audio system.
pub unsafe fn init_voice(params_ptr: *const ParamSnapshot) {
    // SAFETY: called once during single-threaded init
    unsafe {
        VOICE = Some(Voice::new());
        PARAMS = Some(params_ptr);
    }
}

/// Trigger a note on the voice. Call after init_voice.
pub fn trigger_note(note: u8, velocity: u8) {
    // SAFETY: called during init, before ISR is active, or could be called
    // from main thread if ISR is brief enough (single voice, no race)
    unsafe {
        if let (Some(voice), Some(params_ptr)) = (VOICE.as_mut(), PARAMS) {
            voice.note_on(note, velocity, &*params_ptr, chimera_hal::SAMPLE_RATE);
        }
    }
}
```

- [ ] **Step 2: Add voice init and note trigger between audio init and main loop**

After `audio::init_sai1a()` and before `audio::prefill_buffer()`:

```rust
    // Initialize voice with pointer to UI params
    // SAFETY: ui.params lives for the lifetime of the program (static main loop)
    unsafe {
        audio::init_voice(&ui.params as *const _);
    }

    // Trigger a test note (A4 = MIDI note 69, velocity 100)
    audio::trigger_note(69, 100);
```

Wait — `ui` is a `UiState` which owns `params: ParamSnapshot`. We need the ParamSnapshot to be accessible to both the UI and the audio ISR. Currently `UiState.params` is a field.

The simplest approach: pass a raw pointer to `ui.params` to the audio system. The audio ISR reads it. The UI thread writes it. This is a data race in theory, but in practice:
- ParamSnapshot is pod-like (all floats/ints, no pointers)
- The ISR reads a snapshot; a torn read means one frame has mixed old/new values
- This is standard practice in audio firmware (PreenFM3 does the same thing)

So the startup sequence becomes:

```rust
    let mut controls = Stm32Controls::new();
    let mut ui = UiState::new();
    let perf = PerfTracker::new();

    // Audio init
    audio::init_pll3();
    audio::init_sai1a();

    // Connect voice to UI params and trigger test note
    // SAFETY: ui.params lives in main's stack frame which never returns
    unsafe { audio::init_voice(&ui.params as *const _); }
    audio::trigger_note(69, 100);

    audio::prefill_buffer();
    audio::init_dma();
    audio::enable_sai();
```

## Notes

### Why no double-buffered ParamSnapshot yet

The plan uses a raw pointer to `ui.params` that both the UI thread and audio ISR access. This is a controlled data race — the ISR reads while the UI writes. For a single voice with pod-like parameters, this works fine (PreenFM3 uses the same approach). Double-buffered atomic swap is a future optimization when we add polyphony and need consistency guarantees.

### Why WORK_BUF is a static, not stack

The f32 work buffer (64 × 4 = 256 bytes) is a static in RAM_D2 rather than stack-allocated in the ISR. ISR stack space on Cortex-M is limited and shared. A static avoids stack overflow risk and keeps the ISR stack frame small.

### Memory layout after this change

```
RAM_D2 (0x30000000, 32K):
  AUDIO_BUF:  256 × i16 = 512 bytes (DMA buffer)
  WORK_BUF:   64 × f32  = 256 bytes (render scratch)
  VOICE:      ~500 bytes (FM engine state)
  Total:      ~1.3 KB — plenty of room in 32K
```

Note: If VOICE contains a ModalEngine (~40KB for delay lines), it won't fit in RAM_D2. For FM-only initial testing this is fine. When we add Modal, we'll need to place Voice in D1 RAM (512K) or D2 SRAM2 (128K at 0x30020000).
