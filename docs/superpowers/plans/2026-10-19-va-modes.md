# VA MODEs for 0.2.0 Implementation Plan

**Goal:** Six new VA MODEs (FM through zero, PHASE, AM, SOFT SYNC, MAX, LOOPFM), each appended to `VaMode`, BLEND its amount, its own MODE scope, tested, billed and benched.

**Architecture:** One piece of groundwork serves three modes: `VarOsc` learns a *modulated read phase* beside its clean clock phase (`MOD` const path). The clock keeps wraps, sub flips, SYNC marks and jitter exactly as today; the read phase drives the waves and may run backwards, its edges corrected with each crossing's own rate. FM (read rate `inc·(1 + I·m)`), PHASE (read rate `inc + Δ(D·m)`) and SOFT SYNC (read direction flips at OSC 1's wraps, a BLAMP at the turn) are three uses of it. AM and MAX are operators. LOOPFM is a new closed-form oscillator (Smyth, DAFx-26 #36) storing its phase in `VarOsc`'s phase so carry, reset and the sub stay as they are.

**Tech Stack:** Rust (no_std engine, `chimera-engine`), host tests in `chimera-core/tests`, firmware `chimera-stm32`, count scripts (Python, ADR 0118 point 9) in the ledger.

**Spec:** issues #601 #602 #603 #604 #605 #613 (verbatim in (private notes)); ADR 0118 (VA), 0129 (VA glyphs), 0142 (bank-2 door). Papers (text extracted) in (private notes).

## Global Constraints

- Each mode appends one frozen `VaMode` disk code; nothing renumbered: FM = 5 (`"FM"`), PHASE = 6 (`"PHASE"`), AM = 7 (`"AM"`), SOFT SYNC = 8 (ident `"SOFTSYNC"`, shown `SOFT SYNC` if it fits the cell and the focus band, else `SOFT`), MAX = 9 (`"MAX"`), LOOPFM = 10 (`"LOOPFM"`).
- BLEND (the `AMOUNT` param) is each mode's amount. A MODE change goes through the existing duck (no new click path).
- Provenance: first principles and papers only, never GPL code. Each new technique carries `PROVENANCE` lines. LOOPFM credits Smyth, DAFx-26 paper 36 (CC-BY 4.0) in `THIRD_PARTY.md`.
- No `unsafe` without `// SAFETY:`; no heap or blocking on the audio path; every per-block value a new mode reads is ramped across the block (`Ramp`/`step_of`), never snapped.
- MIX, SYNC, RING, XOR and BITS stay bit-identical: `golden_test` (`va_init`) and every existing `va_*` test pass unchanged.
- ADRs from 0158 (0155–0157 are reserved). Never edit an accepted ADR; ADR 0118 is amended by new ADRs only.
- Heavy builds under `(private notes) <cmd>` (waits for other cargo/just, runs `nice -n 15`). One at a time.
- Never stage `chimera.bin` or `docs/chimera-ui-ux-spec.md`. Commits terse, no type prefix.
- No flashing, no hardware. Unit measurements are listed as pending steps.
- Flash: each PR reports `just firmware-orbit`'s bank-1 line (`917504 − n B`) before/after in one line. Below ~40 KB free: put the new DSP behind the bank-2 door (ADR 0142 pattern; `door-check` in `just check` must pass) instead of shaving bytes.
- Voice cost: each mode bills by ADR 0118 point 9's count; ADR 0040's six voices on rev Y (room 4,186: bill ≤ 599 with INIT's +98) must hold or the task stops and reports.

## Review Focus

1. **Leaving a MOD mode on a held note.** After FM/PHASE/SOFT SYNC swaps back to MIX, the sine and the edged wave of a pair must read the same phase (`VarOsc::settle`). Test in Task 1 (`settle_keeps_the_pair_coherent`) and Task 3 (`leaving_fm_settles`).
2. **BLEND automated hard** (0↔1 every block, a CC sweep) in every new mode: no click beyond the existing click rule, no NaN, peak within `peak_safe_everywhere`'s bound. Each mode's DSP task adds its mode to `knobs_sweep_without_clicks`/`peak_safe_everywhere`/`midi_extremes_stay_finite` (or confirms they iterate `VaMode::ALL`).
3. **Top notes at full BLEND** (note 127, CRSE +24): FM's index cap and LOOPFM's `b0` cap keep every read rate under ½ a cycle and the output finite. Covered by `midi_extremes_stay_finite` plus the per-mode cap tests.
4. **STABILITY below 1** in a new mode: jitter draws, carry/restore and phase-run-on behave as in MIX (LOOPFM stores its phase in `VarOsc`). Test in Task 13 (`loopfm_carry_restores`).
5. **A MODE scrolled every block through the new codes** (`mode_scrolled_every_block_settles` must include all 11 modes).

### Task 1: `VarOsc`'s modulated read phase (MOD path)

**Files:**
- Modify: `chimera-engine/src/dsp/va/osc.rs` (`VarOsc`, `render`, `run`, `cross`, `correct`, `NEW`, `reset`, `set_phase`)
- Modify: `chimera-engine/src/dsp/va/mod.rs` (call sites pass `MOD = false`; `settle` at the duck's swap)
- Test: `chimera-core/tests/va_osc_mod_test.rs` (new)
- Create: `docs/adr/0158-va-oscillators-read-a-modulated-phase-beside-a-clean-clock.md`, row in `docs/adr/README.md`

**Interfaces:**
- Produces:
  - `VarOsc` fields `read: f32` (read phase, 0..1) and `dir: f32` (±1). `NEW`: `read 0.0, dir 1.0`; `reset` and `set_phase` set `read = phase`, `dir = 1.0`.
  - `pub fn render<const N: usize, const REC: bool, const SYNC: bool, const FLIP: bool, const MOD: bool>(&mut self, out: &mut [f32; N], mk: &mut [[f32; 2]; N], r: &Ramps, jit: &mut f32, draw: &mut impl FnMut() -> f32, m: &[f32; N], k: (f32, f32))`
    - `MOD = false`: `m` and `k` unused; the code path identical to today (bit-exact). The end of every plain run stores `read = phase`.
    - `MOD = true`, `SYNC = false`: per sample the read rate is `rr = ie·(dir + k.0·m[i]) + k.1·m[i]`, wrapped to the nearest (`rr − floor(rr + 0.5)`), `read = frac(read + rr)` either way; each edge's `u += rr − od[k]`; a crossing's `t = clamp(t0 + over / (rr − od[k]))` and a corner's `|rr − od[k]|/6` computed in the crossing branch only (a divide per crossing, none per sample); the sine reads `read`. Clock `phase`, wraps, `REC`/`FLIP` marks and `draw` exactly as plain.
    - `MOD = true`, `SYNC = true` (reversing sync): a mark `t ≥ 0` in `mk[i][0]` is a turn `t` samples ago. Pre-turn motion `dir·ie·(1 − t)` (edges at `t0 = t`, rate `dir·ie − od`); at the turn a BLAMP of slope jump `−2·dir·ie·(A::slope + B::slope)` at the read phase there (`blamp_into(held, acc, t, …)`); `dir = −dir`; post-turn motion `dir·ie·t` (edges at `t0 = −0.0`). No reset. `k` is `(0, 0)` here.
  - `pub fn settle(&mut self)`: `phase = read; dir = 1.0` (the `u`s stay valid: they are relative to `read`). `VaEngine::render` calls it on both oscillators where the duck swaps `playing`.
  - Test-support only: `pub fn tick_mod(&mut self, inc: f32, m: Morph, rr_extra: f32, turn: Option<f32>) -> Tick` (one sample, `k = (0, 1)`, `m = [rr_extra]`; with `turn` it runs the reversing path) and `pub fn read_phase(&self) -> f32`.
