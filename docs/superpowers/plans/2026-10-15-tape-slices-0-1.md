# TAPE Slices 0 and 1: the DMA Card Layer, Streaming and PLAY Implementation Plan

**Goal:** Build the SD card's DMA read path once, measure it on the unit (slice 0, benches B2–B7), then ship streaming on top of it: PLAY (ONESHOT, LOOP and PING-PONG folded) plays sources bigger than the arena from the card, forward, with designed drop-outs, quiet for writes and fault recovery (slice 1).

**Architecture:**
- **Functional core.** Everything that decides is pure and host-tested:
  - SPI-mode framing, CRC7, CRC16 and token scan in `chimera-fat::sd_proto`;
  - the bus word in `chimera-hal::card_bus`;
  - `SharedCard<D>` in `chimera-fat`;
  - in `chimera-engine::stream`: chunk layout and de-framing, slots, rings, EDF, registry, admission and the cursor.
- **Imperative shell.** Thin: `chimera-board::card_dma` (DMA2, SPI2 registers, the `DMA2_STR0` interrupt), the audio hook in `chimera-stm32`, and the desktop's `card_stream` thread.
- **Banks.** The card layer and registry are bank 1. Spans and the cursor are bank 2, behind `TapeDeck`'s door.

**Tech Stack:** Rust `no_std` on STM32H750 (`stm32h7xx-hal` 0.16, `stm32h7` PAC 0.15, `embedded-sdmmc` 0.10), proptest, loom, `tools/chimera-usb.py`.

**Spec:** `docs/superpowers/specs/2026-10-15-tape-slice1-streaming-design.md` (binding; corrected by this plan's review in commit "TAPE slice 1 spec: corrections from the plan's review"). Umbrella: `docs/superpowers/specs/2026-10-15-tape-sampler-design.md` § 2.3, § 5, § 7, § 9. ADRs 0147, 0145, 0137/0142, 0093, 0087, 0106; 0011 (goldens lock refactors), 0112 (params declare their motion). Bench plan: (private notes). M1 numbers: (private notes). Read the spec, `CLAUDE.md` and the task's spec sections before each task.

**Owner rulings already in the spec:**
- Over budget, a new note steals the oldest streamed voice: released first, then held.
- Every card write while streams play fades them out and back.

**Worktree and branch:** (private notes), branch `tape-sampler-spec`. Work only there. Never push.

## Global Constraints

- **Code rules (CLAUDE.md):**
  - `no_std`, no libc.
  - No heap, no blocking, no panic in the audio interrupt or the card interrupt.
  - No `unsafe` without `// SAFETY:`.
  - Params never snap: every gain change is a per-sample ramp (ADR 0112). `DROP_FADE` is 144 samples (3 ms). `QUIET_FADE` is 480 samples (10 ms).
- **Functional core / imperative shell:**
  - Every rule that can be tested on the host lives in a host-tested crate (`chimera-hal`, `chimera-fat`, `chimera-engine`): framing, CRC, scheduling, admission, the slot state machine, ring and guard logic, the bus word.
  - The board crate only moves bytes and pokes registers.
- **Test-driven (owner, 2026-10-15):** every code task writes its failing test first, runs it red, then the minimum code to pass, then refactors green. No task's code lands without a test that failed first. Tests name behaviour, not functions.
- **Type-driven (owner, 2026-10-15; memory type-driven-development):** if the type system can rule out a mistake, it must; a test covers only what types can't express. Reviewers flag any runtime check or test a type could replace.
  - `ChunkIdx`, `Bill`, `Owner`, `Quiet`, `CardFault`, `SlotState` and `Flow` are types, not bare integers. A slot word's packing (state 2 bits, generation 6, chunk 24) lives behind `Slot`'s methods only.
  - **Units are newtypes, never mixed:** `Lba` (a 512 B block number) vs the command argument, built only by `AddrMode::{Block, Byte}.arg(lba)` from the card type (Review Focus 1 becomes a type, not a remembered shift); `Frames` vs `Bytes`; durations in `Millis`/`Micros`; deadlines in `AudioBlocks`, compared only by signed distance (`until`); rates in `BytesPerSec`; speed as `Ratio`; counts as `StreamCount` (1..=8), `Generation` (mod 64), `SlotIdx`, `VoiceIdx`. Conversions are named methods (`Frames::to_bytes(Packing)`), no `as` casts across units. Task 0 makes them all: card, time and rate units in `chimera_hal::units`, `AddrMode`/`CmdArg` in `chimera_fat::sd_addr`, stream units in `chimera_engine::stream::units`.
  - **States are enums with data,** not flags plus fields: a slot `Empty | Wanted { chunk, generation, deadline } | Filling { chunk, generation } | Ready { chunk, generation }`, the bus `Free | Ui | Stream` (taken only as `Taker::{Ui, Stream}`), quiet `Off | Asked | Held`, a fault `Clear | Read`, a stream's admission `Admitted(Bill) | Refused(Reason)`. Illegal combinations don't compile. A card fill needs a `Claim` from `claim()`, so writing a slot's bytes is safe code.
  - **Constructors validate once:** a `ChunkLayout`, `Extents` (≤ 32 runs) or `HeadSpec` that exists is valid; code past construction never re-checks. Compile-time constants are checked with `const` asserts.

## Review Focus

Five conditions the spec implies but its tests don't exercise, most likely first. Each has a test in the task named.

1. **An SDSC card (≤ 2 GB, byte-addressed).** CMD18's argument is a byte address on SDSC and a block address on SDHC/SDXC. The spec's shell sends `lba` as is. Expected: streams read the right blocks on either card. Pinned by `cmd18_arg_addresses_by_card_type` (Task 0); the shell reads the card type from `SdCard::get_card_type` once per mount into `CARD_ADDR` (Task 7).
2. **A corrupt streamed file whose framing is intact.** `deframe` checks tags and lengths, never the samples, and a streamed load never reads the whole file, so the CRC32 that a whole load checks is skipped. Ruled (below): a streamed load trusts the seal and checks only what it reads. Pinned by `streamed_load_trusts_the_seal` (Task 17).
3. **A ninth streamed source.** The registry is 8 rows; the spec's "32 rows, about 2 KB" was impossible and is corrected. Expected: the ninth refuses at load, with a reason in the focus band, and the project still loads its other Parts. Pinned by `ninth_streamed_source_refuses` (Task 17). **Copy `STREAMS FULL` is provisional:** the controller confirms it.
4. **A note whose own bill exceeds the whole budget** (a +48-semitone PITCH route gives `ratio_max` ≈ 16, 658 KB/s). Expected: it is refused before allocation and never steals every other stream first. Pinned by `admit_refuses_a_note_over_the_whole_budget` (Task 13).
5. **A loop shorter than a chunk, or wholly inside the loop-start head.** Expected: it loops seamlessly from RAM and never asks the card. Pinned by `short_loop_on_streamed_source_stays_in_ram` (Task 15).

**Controller rulings (2026-10-15):**
- **Streamed loads skip the whole-file CRC32.** Item 2's full read-through costs ~1.3 s a MiB at every project load (a TRON set ~4.5 s). The file was verified when it was sealed (write, read back, verify), every block read is CRC16-checked on the wire, `deframe` checks framing, and any 12-bit sample is a valid sample: a rotted file plays noise in the bad span, never a fault. Task 17's test becomes `streamed_load_trusts_the_seal` (the heads are still checked as they're read) and CARD TEST gains a full verify of the card's sources (umbrella slice 3). Cost if wrong: a rare rotted bed plays a burst of noise.
- **`STREAMS FULL`** is the copy for the ninth streamed source.
- **`fault card`** goes on `orbit,fault-inject` as planned. If that build doesn't fit FLASH, the fault step of the unit proof runs on the `bench-stress,bank2` build with all slice-1 code instead; the rest of the proof stays on the product build.

**Spec issues ruled in the plan, for the controller's eye:**
- `card fault` is a bench verb, so it is absent from the ORBIT build that the unit proof uses. The plan adds `fault card` to `fault-inject`, and step 6 runs on `--features orbit,fault-inject` (Task 20). If that set does not fit FLASH, the controller rules.
- The bench verbs run for 10–30 min. The console answers one request in a UI pass, with 2 s of silence allowed. So every `card dma` verb starts a run and answers at once, and `card dma report` polls it (Task 9). The run's consumer is the audio interrupt (`stream::bench`), so B6's redraws and save are the real UI's.
- B5 must measure the raw write stall. It runs in slice 0, before Task 19 adds quiet. A later re-run of B5 takes `SharedCard::write_raw` (bench builds only, Task 19).
