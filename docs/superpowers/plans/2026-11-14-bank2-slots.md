# Bank 2 Slots Implementation Plan

**Goal:** Grow bank 2 from S0–S3 to all of S0–S7 (1 MB). Bootloader 1.09's MIXER and EDIT slot entries hold restart stubs, so a held button boots bank 1. An installer guard never overwrites a slot that isn't Chimera's.

**Architecture:** One `.bank2` output section of exactly 1 MB, filled with 0xFF. It has four fixed points: the MIXER reserve at +0x80000, S5's marker at +0xBFFE0, the EDIT reserve at +0xC0000 and S7's marker at +0xFFFE0. The pure parts live in `chimera-image` and are host-tested against `SimFlash` with tears and ECC faults: the slot bytes, the guard, the install order and the boot marks. The board adds masked flash reads, the 1 MB MPU region and the guard's place in the boot and console installs. Tooling (`chimera-usb.py`, `chimera-utils check-slots`, the Justfile budgets) follows.

**Tech Stack:** Rust no_std (`chimera-image`, `chimera-board`, `chimera-stm32`), rust-lld linker scripts written by `chimera-stm32/build.rs`, Python 3 (`tools/chimera-usb.py`, unittest), just.

**Spec:** `docs/superpowers/specs/2026-11-14-bank2-slots-design.md` (f83c11d1) and ADR 0272. Re-review should-fixes N1–N5 are folded in here, as noted per task.

## Global Constraints

- Bank 2 is 0x08100000–0x081FFFFF. `BANK2_LEN` = 1 MB, `FORMAT` = 2, and `body_len` = 1 MB − 256 exactly. The `.bk2` is 1,048,576 B.
- The fixed points are offsets from 0x08100000: MIXER reserve 0x80000 (1 KB), S5 marker 0xBFFE0 (32 B), EDIT reserve 0xC0000 (1 KB), S7 marker 0xFFFE0 (32 B). Every other byte the link leaves is 0xFF.
- The stub's code word holds SP `0x2002_0000` and reset `base + 9`. Its code is `ldr r0,=0x08020000; ldr r1,=0xE000ED08; str r0,[r1]; dsb; isb; ldr r1,[r0]; ldr r2,[r0,#4]; msr msp,r1; bx r2`.
- The tag word holds literals `0x08020000, 0xE000ED08` at 0x20, 0xFF ×8, then `CHIMERA-SLOT`, version 1, slot (0 MIXER, 1 EDIT) and 0xFF 0xFF at 0x30. The marker is `CHIMERA-SLOT-END`, version 1, slot, then 0xFF to 32 B.
- The order a slot: erase S5 (skipped if the guard found it erased) → S5 marker → erase S4 → tag word → code word. These are separate writes; EDIT is the same with S7/S6. A slot whose `Evidence` is `Marker` or `Mark` goes S4 first: erase S4 → tag → code → erase S5 → marker. Invariant: one clean tag or marker survives at every instant. The whole install: S0, S1–S3, MIXER slot, EDIT slot, the body skipping the six slot words, the header, the commit word last.
- The guard rule: (a) S4's tag word clean, or (b) S5's marker clean → ours. Otherwise (c) every word is erased, except S4's code word, S4's tag word and S5's marker word. Each of those three may be erased, ECC-flagged, or `(word & expected) == expected` (N1).
- The refusal screen reads `NOT INSTALLED` / `THE MIXER SLOT HOLDS` / `OTHER CODE.` / `NOTHING WAS WRITTEN.` (EDIT for the EDIT slot), for 5 s or any button. `status` reads `bank2 slot foreign mixer|edit`, and ABOUT reads `SLOT IN USE`.
- MPU region 2 is 0x08100000, 1 MB: RASR Read 0x1608_0027, Write 0x1300_0027, Open 0x0602_0027. Region 1 is unchanged.
- Never: write or erase the option bytes, bank-1 registers, a bank or mass erase, or 0x08000000. Never ROM DFU into bank 2.
- No `unsafe` without `// SAFETY:`. No heap or blocking in the audio interrupt.
- Builds: `nice -n 15 env CARGO_BUILD_JOBS=10 <cmd>`, and at most two heavy builds at once. Targeted tests in each task; the full `just check` in Task 9.
- No flashing and no USB descriptor change in Tasks 1–10. Never wrap `chimera-usb.py update` in a timeout. Task 11 is OWNER-GATED.
- Commits are terse, with no type prefix.

## Review Focus

1. **A `.bk2` of the wrong size or format** (a 0.3 file in the card root, or one truncated by a host copy) must judge `Format(1)` or `Corrupt` and never reach the guard or an erase. Test in Task 1: `old_or_short_images_never_install`.
2. **A tag text with a newer version byte** (a later Chimera's stub) must read as ours, and a tag-looking text at the wrong offset must not. Test in Task 2: `tag_version_is_ignored_offset_is_not`.
3. **A refusal must leave MPU region 2 in `Read`, not `Write`**, so the next console `flash` or judge reads normally (N3). Task 8: a host-visible `after_refusal()` that returns `Mpu2::Read`, plus gate 8.
4. **A boot that refuses every power-on must not grow its cost** (no retries, no card writes). Test in Task 4: `refused_boot_repeats_without_writing`.
5. **`update` from 0.2.0 firmware, not only 0.3,** must take the flash-first path (N4's prefix match). Test in Task 6: `old_02_firmware_takes_flash_first`.

- [ ] **Step 3: Implement `guard`**

For each slot not in `ours`:
1. Read the tag word. If it is clean (no `ecc`) and bytes `0x10..0x1C` of the word equal `TAG`, the slot is ours.
2. Otherwise read the marker. If it is clean and bytes `0..16` equal `MARKER`, the slot is ours.
3. Otherwise scan every word of both sectors in address order. The three own words pass if erased, `ecc`, or `(w & expected) == expected` bytewise; any other word passes only if all 0xFF and not `ecc`.

A slot is planned erased only if all of both sectors read 0xFF. Return at the first foreign slot.

## What this plan does not settle

- **Which code moves into the S4/S6 groups.** Task 9 links them empty. The first 0.4 feature that needs the room places its glob group there, under its own plan.
- **A masked read that doesn't hold.** If Gate 1b shows a flash double-ECC error isn't a precise, BFHFNMIGN-maskable fault, the fallback marks carry it. The owner's open question 2 (a foreign slot with an ECC error would be erased) then needs an answer before release.
- **`update` from a unit already in DFU** (coming back from stock) is not planned; the card route is the documented path.
