# Plan: the v6 editor in Elm (#1019, #1014's screens)

Design: `docs/superpowers/specs/2026-11-19-editor-ui-design.md`.
Branch `editor-ui` (worktree (private notes), from origin/0.4 d7611695).

Every task is built test-first: a failing elm-test, then the code, then `just editor-test` green, which means elm-test plus elm-review with the full rule set, every `let` annotated and no catch-alls. Each task ends in a commit with. The editor must keep working against `just editor-sim` and `just editor-e2e` after every task.

## 1. Tokens and the component library

1. `Ui.Tokens`: the `Theme` type, DAY and NIGHT token sets in `public/style.css` (v6's `theme.css` values), theme from the OS or a stored choice (`localStorage`, behind try/catch in the shim).
2. `Ui.Control`: `Msg`, `Reading`, `Drag`, `update`. Port slice 1's `Gesture` drag and wheel maths into it, unchanged in behaviour, and keep `GestureTest` passing against the move.
3. `Ui.Knob`, `Ui.Fader`, `Ui.Toggle`, `Ui.Selector`, `Ui.Menu`, `Ui.WordRow`. Each has its own test file covering:
   - the builders;
   - which `Msg` each hand gives;
   - the width contract: the sizing style is identical across five readings, the shortest and longest text included;
   - the ARIA roles.
4. `Ui.Screen` (crop fallback first, `<chimera-screen>` later), `Ui.Module` (title bar folds the body, summary when folded, jacks), `Ui.Row` (a pair or one full module, fold together), `Ui.Page` (top bar, chips, theme switch, rows).
5. `Ui.PatchBay` and `Ui.MatrixGrid`: one `Routes` model, two views, a PATCH | MATRIX toggle, attenuverter signs as amber or blue.
6. `Ui.PadStrip`: KIT plus PAD 1–12, the unit's pad names.
7. `Gallery.elm` plus `just editor-gallery`: every component in every state, DAY and NIGHT, and a JITTER probe that steps every control and prints the largest box shift.

## 2. ALGO on live protocol 3 data

1. `Layout.Shared`: FILTER, FILTER MOD, VOICE FX, AMP · OUT, ENV 1–3, LFO 1–3, PITCH as modules, with placement by meaning.
2. `Layout.Algo` rewritten on it: ALGORITHM, OP 1–6 (each OP's panel by its WAVE variant), MOD.
3. `View.EnginePage`: the schema plus layout plus `Model` readings become `Ui.Page`. An OTHER module catches anything unplaced.
4. Main switches to it and slice 1's `View.Algo`/`View.Controls` are deleted.
5. Tests against the ALGO fixture: every address placed exactly once or in OTHER, variants followed, and a `Pick`/`Edit` reaches `Model` as before.

## 3. VA, MODAL, TAPE, DRUM

1. `Layout.Va`, `Layout.Modal`, `Layout.Tape` with the same tests against their fixtures. TAPE's SOURCE is read-only (#1015).
2. `Layout.Drum` plus `Ui.PadStrip`: the KIT view (KIT pads, the whole kit's voice modules) and the PAD n view (the pad's pages, ROUTE 1–4 as a live patch bay over `PADn_RTk` params), then MOD.
3. Main shows the page for the followed Part's engine.

## 4. Glyphs: `chimera-screen` (WASM), alongside 1–3

1. A new crate `chimera-screen` (cdylib, wasm32-unknown-unknown, depends on chimera-core):
   - a headless `UiState` mirror;
   - exports `init(engine)`, `set(addr, stored)`, `render(page, region) -> ptr` to an RGB565 buffer.
   It has no wasm-bindgen, only plain `extern "C"` exports.
2. `just editor-screen` builds it into `editor/public/screen.wasm`, with the size measured.
3. `ports.js` defines `<chimera-screen>`, and `Ui.Screen` uses it.
4. Host tests in the crate: a render of ALGO's chart for two MORPH values differs, and a render matches the desktop simulator's frame for the same state.

## 5. Unit pages

MIXER, ORBIT, SETTINGS and MIDI MAP need `ed` addresses that don't exist (see the design). Stop after 3 and report the protocol work each needs.
