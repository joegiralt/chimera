# DRUM slice 1: types, first kernels, KIT Part, KIT pages — Implementation Plan

**Goal:** A DRUM Part on the desktop simulator: pick DRUM INIT, play a 12-pad kit over MIDI (C0–B0 the pads, C1 up the selected pad chromatic), with chokes, and edit each pad's machine and knobs on typed KIT / KEYS / MCH / MORE pages. Twelve of the 28 approved machines, on four kernels.

**Architecture:** A typed layer (`dsp/drum/types.rs`) comes first; every later task consumes it. Machines are a closed enum with a const law table that turns a pad's stored `KnobSet` into a typed kernel-params enum; kernels are no_std, no-alloc rewrites of the host prototypes, nulled against them. The kit lives on the Part (not in `ParamSnapshot`): 12 compact `Pad`s; a hit copies its `Pad` into the voice as a `DrumHit`. FILTER, AMP (envelopes), LFOs and MOD are the Part's Sound blocks, shared by every pad in this slice.

**Tech Stack:** Rust no_std (`chimera-engine`, `chimera-core`), desktop simulator (`chimera-desktop`), host null tests in `chimera-utils`.

**Spec:** `docs/superpowers/specs/2026-11-10-drum-engine-design.md` (rulings 2026-11-10, ship list, audition marks 2026-11-11). Integration map: survey of 2026-11-12 (findings repeated where a task needs them).

## Global Constraints

- **Type-driven, mandatory (owner, 2026-11-12: "for the love of god").** No bare `u8`/`u16`/`f32`/`u32` for units, ranges, indices, codes or modes where a newtype or enum fits; no runtime check a type could replace; constructors return the type (clamped) or `Option`, never panic. Pages bind typed cells (`ParamSlot` / `SlotBinding`), never bare indices. Reviewers fail a task that ports the prototypes' `Knobs = [f32; 8]`, `&str` kernels, `Box<dyn Machine>`, f64 or `Vec`.
- No `unsafe` without `// SAFETY:`; no heap; audio path never blocks or allocates; no libc.
- Machines: Machinedrum structure and knob sets from the manual only; our algorithms and names (ADR 0114). No firmware, ROM, tables or sample data.
- Flash: bank 2 has ~400 B free, so per ADR 0251 DRUM goes to bank 1: raise `tools/bank1-budget.txt` lines with `; ADR 0251 +N DRUM slice 1 (from X)`, `#[inline(never)]` on kernel entry points, kept outside the bank-2 globs in `chimera-stm32/build.rs`. Report bank-1 delta per task that grows it, in one line.
- Sound never snaps: knob edits go through the same glide path as `BlockRef::Part` edits.
- Hidden gestures get hints: MIX + MINUS / PLUS (pad step) shows a focus-band hint on the KIT band and the PAD cell.
- Full-word labels where they fit (KICK, SNARE, COWBELL, SWEEP TIME).
- Builds through ``, `nice -n 15`, `CARGO_BUILD_JOBS=10`; targeted tests per task, `just check` before the PR.
- Commits: terse, no type prefixes.

## Review Focus

1. **Every knob at its extremes, at velocity 1 and 127:** a reasonable player expects sound or silence, never NaN, inf or a blast. Task 3 renders every slice-1 machine at all-0, all-127 and each single knob at 0/127 and asserts finite output, peak ≤ +6 dBFS.
2. **A 0.3 project (no kit block) and a 0.3 Sound library:** load with the default kit, no panic, other Parts unchanged (Task 6).
3. **Switching a ringing DRUM Part to VA (or VA to DRUM):** voices end through the fade; no stale `DrumHit` is replayed into a VA slot (Task 5).
4. **A 64th-note roll on one CUT pad at 300 BPM for 10 s:** the pool returns to 0 active voices after the tails; no leak (Task 5).
5. **MIX + MINUS on the MTX page of a DRUM Part:** still deletes the route; it steps the pad only on KIT / KEYS / MCH / MORE (Task 8).
